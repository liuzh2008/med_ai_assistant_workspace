## 项目概述

医疗AI辅助诊疗系统（MedAiAssistant）V1.0是一个集患者管理、AI辅助诊断、DRG分析、MCC筛查等功能于一体的医疗信息化平台。本系统采用前后端分离架构，前端基于Vue 3框架开发，后端采用Spring Boot 3框架，支持与医院HIS、PACS、LIS等医疗信息系统进行数据对接。

**系统核心特性：**
- AI辅助诊断分析：基于大语言模型技术，自动分析患者病历信息提供诊断建议
- DRG智能分组：支持DRG（疾病诊断相关分组）智能匹配和盈亏分析
- MCC/CC并发症筛查：智能识别可能影响DRG分组的并发症
- 患者全景信息管理：整合多维度医疗数据，支持快速浏览和掌握患者病情
- Prompt模板化管理：支持多种诊疗场景的AI分析模板管理
- 分布式执行服务器架构：采用"主服务器 + 执行服务器"双节点分离架构

## 软件著作权申请材料清单

根据《计算机软件著作权登记申请材料详细要求》，申请软件著作权需要准备以下材料：

### 1. 源代码文档
- **数量要求**：代码量≥3000行，提交连续前30页 + 后30页（共60页）
- **格式要求**：A4纸张，每页≥50行有效代码，小五号字体，固定行距12磅
- **内容要求**：从程序起始部分开始，包含程序结束标志

### 2. 用户操作手册
- **页数要求**：根据源代码行数确定最低页数要求
- **内容结构**：软件概述、主要功能描述、运行环境说明、操作流程说明
- **格式要求**：A4纸张，每页≥30行，有图除外

### 3. 申请表
- 软件全称、版本号、主要功能描述
- 开发完成日期、首次发表日期
- 申请人信息和联系方式

### 4. 身份证明材料
- 个人申请：身份证正反面复印件+申请人签字
- 企业申请：营业执照副本复印件+公章+法定代表人签名

## 源代码文档要求

### 提交规则
- 代码量≥3000行：提交连续前30页 + 后30页（共60页）
- 代码量<3000行：需全部提交，仍需满足格式要求

### 排版规范
| 项目 | 要求 |
|------|------|
| 纸张 | A4纸（297mm×210mm） |
| 每页行数 | ≥50行（最后一页除外），空行和注释不计入 |
| 字号 | 不大于13号（建议小五号/10.5pt） |
| 字体 | 等宽字体（推荐宋体） |
| 行距 | 固定值12磅 |
| 页眉 | 左上角标注"软件名称+版本号"（须与申请表完全一致） |
| 页码 | 右上角阿拉伯数字连续标注（格式：第X页 共60页） |
| 装订 | 单面打印，左侧预留1cm装订线 |

### 代码内容注意事项
- 需删除所有空行和无意义注释
- 保留版权声明和作者信息
- 框架自动生成代码占比建议不超过20%
- 不限编程语言
- 避免提交加密/压缩的不可读格式

## 用户操作手册要求

### 类型选择
以下类型任选一种：
- 用户操作手册（最常见）
- 用户使用说明书  
- 设计说明书
- 用户设计说明书

### 页数要求
| 源代码行数 | 说明书最低页数 |
|-----------|--------------|
| ≤ 3000行 | 5页以上 |
| 3000 ~ 10000行 | 15页以上 |
| > 10000行 | 20页以上 |

### 内容结构
- **软件概述**：功能介绍、开发背景
- **主要功能描述**：核心功能清单
- **运行环境说明**：操作系统、硬件要求、依赖环境
- **操作流程说明**：用户操作步骤
- **功能界面截图**：间隔2-3页至少出现一次截图，须清晰完整，配文字说明
- **常见问题解答**（可选）

### 排版要求
- A4纸，每页 ≥ 30行（有图除外）
- 页眉标注软件名称和版本号，须与申请表完全一致
- 需有封面和目录（不计入页数）
- 不能有水印、大段空白
- 超过60页时提交前30页和后30页

## 申请表填写要点

### 基本信息
- **软件全称**：包含"品牌+功能+软件"，如"XX医疗AI辅助诊疗系统V1.0"
- **版本号**：统一为 V1.0 格式；若版本号 ≥ 2.0 需提供上一版本软著证书
- **主要功能描述**：500-1300字，与源代码实现一一对应

### 重要日期
- **开发完成日期**：软件固定在有形载体上的日期，须 ≤ 首次发表日期
- **首次发表日期**：可与开发完成日期相同
- 开发完成日期应早于申请日期

### 一致性要求（重点）
⚠️ **申请表、源代码页眉、说明书页眉中的软件名称和版本号必须完全一致！**

## 申请流程与时间

### 流程步骤
1. 注册账号（ccopyright.com.cn）
2. 实名认证
3. 填写申请表
4. 上传鉴别材料（源代码 + 说明书，PDF 或 Word 格式）
5. 上传证明材料
6. 在线缴费
7. 提交申请
8. 形式审查（5个工作日内）
9. 实质审查（45-55个工作日）
10. 领取证书

### 时间和费用
| 办理方式 | 审查周期 | 费用参考 |
|---------|---------|---------|
| **普通申请** | 60个工作日（约3-6个月） | 290-300元 |
| **加急（30天）** | 30个工作日 | 450-600元 |
| **加急（7天）** | 7个工作日 | 需额外付费 |

## 常见问题与预防措施

### 源代码相关
| 驳回原因 | 具体表现 | 预防措施 |
|---------|---------|---------|
| **代码量不足** | 每页行数少于50行，空行/注释计入 | 删除空行和注释，确保每页≥50行有效代码 |
| **格式不规范** | 字号过大、页眉缺失或与申请表不一致 | 严格按排版规范执行，提交前逐页核查 |
| **连续性破坏** | 前30页/后30页中间有缺页 | 确保前后各30页内容完整连续 |
| **代码相似度高** | 大量复制开源代码或与已登记软件雷同 | 确保核心功能代码为自主开发，不超过20%框架代码 |

### 申请表相关
- **名称不一致**：申请表与源代码/说明书页眉名称不同 → 三处名称必须完全一致
- **版本号格式错误**：如写成"1.0"而非"V1.0" → 统一使用V+数字格式
- **日期填写错误**：开发完成日期晚于首次发表日期 → 严格遵守日期逻辑关系
- **功能描述与代码不符**：描述了代码中未实现的功能 → 逐一对照核实

### 材料缺失
- **证明材料缺失**：企业申请未加盖公章、未签字 → 提交前逐项核对材料清单
- **说明书不符**：页数不足、缺少截图或截图模糊 → 按页数要求补充，确保截图清晰

### 软件名称问题
- **名称过于通用**：如"管理系统V1.0"无法区分 → 加入品牌或行业特征词
- **名称重复**：与已登记软件完全相同 → 提前在平台检索确认名称唯一性后再提交申请

- [ ] 源代码每页有效代码行数 ≥ 50行（空行和注释已删除）
- [ ] 源代码字号 ≤ 13号，使用等宽字体，行距固定12磅
- [ ] 源代码页眉标注软件名称+版本号，与申请表完全一致
- [ ] 源代码页码格式正确（第X页 共60页），连续编排
- [ ] 说明书页数满足最低要求（≥15页或≥20页）
- [ ] 说明书包含完整截图，每2-3页至少一张，截图清晰
- [ ] 说明书页眉软件名称+版本号与申请表完全一致
- [ ] 说明书有封面和目录（不计入页数）
- [ ] 申请表软件全称格式正确（含品牌+功能+软件+版本号）
- [ ] 申请表功能描述字数在 500-1300字 之间，与代码实现一一对应
- [ ] 开发完成日期 ≤ 首次发表日期 < 申请日期
- [ ] 身份证明材料完整（企业：营业执照+公章+签名；个人：身份证+签字）
- [ ] 所有材料软件名称、版本号三处完全一致（申请表、源代码页眉、说明书页眉）

## 项目技术规格说明

### 系统架构
系统采用前后端分离架构，主要技术栈如下：

**后端技术栈：**
- Spring Boot 3.5.8
- Java 21
- Oracle Database 19c及以上
- Spring Data JPA
- Spring WebFlux
- HikariCP连接池

**前端技术栈：**
- Vue 3.2.13
- Element Plus 2.10.2
- Axios 1.10.0
- Vue Router 4.5.1
- Vuex 4.0.2

### 核心配置
系统支持多数据源配置，可动态切换MySQL和Oracle数据库：

**数据库配置示例：**
```properties
# 数据库类型配置
app.datasource.type=oracle

# Oracle服务器配置
oracle.server.active=local
oracle.server.local.ip=127.0.0.1
oracle.server.local.sid=FREE

# HikariCP连接池优化配置
spring.datasource.hikari.maximum-pool-size=15
spring.datasource.hikari.connection-timeout=10000
```

### API接口示例
系统提供丰富的RESTful API接口，支持患者管理、AI分析、DRG分析等功能：

**主要API接口：**
- `/api/medicalrecords/emr-by-patient` - 根据patient_id查询病历记录
- `/api/patients/{patientId}/diagnoses` - 获取患者诊断数据
- `/api/ai/patient-comprehensive-info` - 获取患者综合信息
- `/api/lab-results/by-patient/{patientId}` - 查询化验结果

### 安全特性
- AES加密数据传输
- SSL/TLS安全通信
- 用户身份认证和权限控制
- 操作日志审计

### 监控告警
- 系统健康监控阈值设置
- 业务指标监控和告警
- JVM性能指标收集
- 自定义监控系统
