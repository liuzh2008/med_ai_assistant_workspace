# 查房（Ward Round）

## 适用场景 / 触发条件

- 日常查房或三级医师（主治 48h 内、主任 72h 内首次查房）后，需书写查房记录/日常病程记录（流程步骤 #10-#13）；
- 医生在床旁说"帮我写一下今天的查房记录"；
- 需追踪当日检验/检查回报、对比趋势，或调整医嘱后保持病程与医嘱一致。

## 执行步骤（编号）

1. **患者锚定**：调用 `medai_patient_list_by_department` 确认当前患者（病区/床号），`medai_patient_basic_info` 获取脱敏基本信息与当前阶段（可用 `medai_patient_flow_status` 看患者处于入院/诊疗/手术/出院哪一期）。
2. **床旁取数**：
   - 诊断与病情：`medai_patient_diagnoses`、`medai_patient_basic_info`；
   - 检查检验回报：`medai_lab_results`（检验趋势）、`medai_exam_results`（检查报告）；
   - 医嘱现状：`medai_patient_orders`（长期/临时，判断本次查房调整内容）；
   - 既往文书：`medai_medical_records`（近次病程记录，保证连续性与衔接）。
3. **病情评估**：向医生确认本次查房要点（症状变化、查体发现、上级医师意见），agent 只整理不推断；可调用 `medai_diagnosis_analyze` 做辅助分析（供医生参考）。
4. **生成查房记录/日常病程记录**：调用 `medai_record_generate`（模板：上级医师查房记录 / 病程记录）生成草稿——病情变化、查体、检查回报、医嘱调整依据、后续计划；快速类模板可走 `medai_record_generate_sync` 同步等待（草稿卡片呈现）。
5. **医嘱同步建议**：查房后医嘱变更与病程记录**双写一致**——调用 `medai_patient_orders` 核对医嘱变更，若病程未反映调整则提示医生补充；医嘱调整建议需医生审批，不直接写回。
6. **审核与保存**：草稿呈现给医生审核，确认后按正式病历落库流程处理（见 medical-record-save 剧本），agent 不直接落库。

## 文书格式要点

- **上级医师查房记录**：查房时间 → 上级医师姓名/职称 → 病情汇报（当前病情与诊疗经过）→ 查体/检查要点 → 上级医师查房意见（诊断修正、治疗方案调整）→ 签名栏（医生本人）。
- **日常病程记录**：记录时间 → 病情变化 → 查体与生命体征 → 检查检验回报 → 医嘱调整依据 → 诊疗计划；频次：病危≥1 次/日、病重≥1 次/2 日、稳定≥1 次/3 日。
- 病程记录与医嘱/检查回报**必须当日数据一致**，时间顺序清晰。

## 审核与保存要求

- 查房记录/病程记录为 AI 草稿，**医生审核后**才可生效；
- 落库走审批通道（草稿→审核→审批→diff 留痕），agent 不直接写正式病历；
- 医嘱变更仅给建议，审批权在医生。

## 注意事项（脱敏/患者锚定）

- 每次取数前确认患者 ID（床旁场景易串患者）；
- 只整理医生口述与系统数据，不虚构查体发现或上级医师意见；
- 检验/检查结果展示用报告单卡片（明文报告不进模型上下文），agent 只引用脱敏结论；
- 病程记录必须反映医嘱实际变更，发现双写不一致时明确提示。
