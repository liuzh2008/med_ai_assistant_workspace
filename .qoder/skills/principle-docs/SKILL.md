# 项目原则文档统一入口（Principle Docs）

## 定位（先读这一句）

本技能是**路由 + 门禁**，不是内容本体。`doc/原则/` 下的四份文档才是唯一事实来源（Single Source of Truth）。

> ⚠️ **禁止把原则文档正文复制进本文件或其他任何技能**。文档演进只改文档；本文件只维护"何时读哪份、读完必须做什么"。
> 本文件摘要与文档不一致时，**以文档为准**。

## 加载即执行（4 步）

1. **定界**——先判本次问题属于 `流程 / 模板 / 数据 / 实现` 哪一类。定错类会直接导致改错层（用改 Prompt 去掩盖流程缺陷，是最常见的返工来源）。
2. **路由**——按下方路由表 `read` 原文，**不得凭记忆或凭本文件摘要执行**。
3. **执行**——按文档的七步法、契约八要素、通用禁止项清单落实改动。
4. **自检与沉淀**——收工前逐条走"开工前 6 问 / 收工前 5 条 / 红线"；新提炼的原则写回 `doc/原则/`，工程事实写回 `记忆库/`。

## 门禁骨架（速用；完整判据以文档为准）

### 开工前 6 问

1. 这是**流程 / 模板 / 数据 / 实现**问题中的哪一类？
2. 这个环节**模拟谁**，他的权限边界是什么？
3. 涉及的是**哪种风险不对称**（哪种错更不可接受）？
4. 不确定的内容放**哪个容器**，措辞怎么写？
5. 改动沿**哪条生效链路**、多久到用户眼前？（运行时真实来源常与源码仓库不是一处）
6. 改动是否动了**输入开头字节**（缓存前缀）？是否保住"稳定内容靠前"？

### 收工前 5 条

1. 模板 + 标准文档 +（必要时）护栏代码 + 数据流边界 + 呈现，**五层是否一致**？
2. **禁止项清单**是否逐条核对？
3. 是否留下**可对照的产物**（事实基线 / 契约 / 样本 / 实施记录）？
4. **红线**是否有证据？
5. **原则是否已沉淀**，下一次能被复用？

### 红线（任何后续优化都不得突破）

1. 输入条目**零丢失**；
2. **保留率 100%**（唯一允许的"删除"是建议，且仅限确认性矛盾）；
3. 断言**可溯源率 100%**；
4. **解析链零破坏**；
5. 辅助/不确定内容**不进业务数据流**（不进正式文书、结算、上报、质控与对外接口）。
