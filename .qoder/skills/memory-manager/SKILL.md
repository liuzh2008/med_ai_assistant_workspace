# 记忆管理（Memory Manager）

本项目有自动维护的长期记忆库 `记忆库/`，由 agent 在每个会话中自动读写，**不需要用户手动要求**。

## 记忆库结构

```
记忆库/
  索引.md           ← 入口：文件结构说明 + 维护规则 + 检索指引
  决策与设计.md      ← ADR：架构决策、技术选型、设计权衡
  踩坑与教训.md      ← 已解决问题：根因 + 修复方法
  环境与配置.md      ← 服务器/端口/账号/SSH/构建部署配置事实
  命令与流程.md      ← 常用命令、操作流程、脚本用法
  会话记忆.md        ← 每会话产出速记，按日期分区
```

## 自动维护流程（每个会话必须执行）

### 会话开始时
1. 用 `read` 读取 `记忆库/索引.md`，恢复项目记忆上下文。
2. 若任务涉及某主题，继续读取对应主题文件（如部署任务读 `环境与配置.md`）。

### 会话中（识别到关键信息时）
判断是否属于以下五类之一：
- **决策**：架构选择、技术选型、设计权衡 → `决策与设计.md`
- **踩坑**：已解决并验证的问题（含根因与修复）→ `踩坑与教训.md`
- **事实**：服务器地址、端口、账号规则、环境变量、构建部署配置 → `环境与配置.md`
- **流程**：可复用的命令序列、操作步骤、脚本用法 → `命令与流程.md`
- **产出**：本次会话完成的功能、改动、结论 → `会话记忆.md`

满足条件时，立即：
1. 用 `edit`/`write` 向对应文件**追加**条目，格式为：
   ```markdown
   ### YYYY-MM-DD 标题（一句话结论）
   - 细节：路径/命令/原因等可复现信息
   - 关联：相关文件或技能
   ```
2. 若追加的是新主题条目，同步在 `记忆库/索引.md` 的文件登记行补充说明（可选）。
3. 已有同主题条目时，**更新**而非重复添加。

### 会话结束时
- 若本会话还有未落盘的产出，追加到 `会话记忆.md` 的对应日期分区（无则新建 `## YYYY-MM-DD`）。

## 质量要求
- 条目必须**可执行、可复现**：包含结论 + 关键细节（路径/命令/原因）。
- 不写入：闲聊、临时性内容、可随时从代码或文档推导的内容。
- 简洁优先，单条 2~6 行为宜，避免冗长。

## 检索
- 用户问"之前是怎么做的/为什么/配置是什么"等历史问题时，先 grep `记忆库/` 目录，再 read 命中文件，用检索结果回答并标注来源。
