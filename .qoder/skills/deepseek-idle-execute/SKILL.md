# DeepSeek 空闲时段执行（deepseek-idle-execute）

把当前任务挂起，等 DeepSeek 的空闲时间段自动执行，避开高峰期（高峰时段慢/贵/易限流）。

## 空闲窗口（默认口径，可在使用时按用户要求调整）

| 时段 | 状态 |
|---|---|
| 12:00 - 14:00 | 空闲（午间窗口） |
| 18:00 - 次日 09:00 | 空闲（夜间窗口，跨午夜） |
| 09:00 - 12:00、14:00 - 18:00 | 繁忙 |

## 工作流程

### 1. 确认任务与目标

- 向用户确认：任务内容、关键步骤、交付物/验收标准；期望执行时刻默认取"下一空闲窗口起点"，用户另有指定则按用户口径。
- 先 `get_goal` 检查会话中是否已有 active goal：有则以其实时 objective 为任务基础，无则用用户描述构建。

### 2. 时间判定与时间差计算（pwsh `Get-Date`）

- 取当前本地小时 h（0-23），判定：
  - `12 <= h < 14` → 空闲（午间）
  - `h >= 18 或 h < 9` → 空闲（夜间，含跨午夜）
  - `9 <= h < 12` → 繁忙，下一窗口起点 = 今天 12:00
  - `14 <= h < 18` → 繁忙，下一窗口起点 = 今天 18:00
- 计算时间差（秒）= 窗口起点 − 当前时刻，向用户播报："预计 HH:MM（约 X 分钟后）自动开始执行"。
- 若当前已在空闲窗口内：无需挂起，直接按第 5 步执行，并告知用户"当前即为空闲时段"。

### 3. 挂起任务（goal，已验证机制）

- 无 goal：`create_goal`；有 goal：`get_goal` 取精确 goal_id/revision 后 `update_goal` action edit。
- objective 按此模板填写（时间 + 任务内容替换为实际值）：

  > 在 <YYYY-MM-DD HH:MM>（约 <X> 分钟后，DeepSeek 空闲时段）自动继续并完成 <任务>：<关键步骤与验收标准>。若当前时刻早于该时间，仅保持等待（后台睡眠），不要开始实质工作。

- `max_goal_rounds` 留足余量（建议 ≥ 8，覆盖等待 + 执行阶段分轮）。

### 4. 窗口外等待（关键：零 LLM 空转）

- **禁止**"每轮醒来看一眼时间就结束本轮"的空转方式：goal 续跑是背靠背的（idle 即排下一轮），空转会在高峰时段反复消耗 LLM 调用，违背本技能初衷。
- 正确做法：**在同一轮内后台睡眠到窗口起点**：
  1. 起后台 job：`pwsh` 且 `run_in_background: true`，命令 `Start-Sleep -Seconds <时间差>`（后台 job 不受工具超时限制）。
  2. 用 `job_output` 反复 `wait: true` 阻塞本轮：单次 wait 上限为部署配置（默认 10 分钟），超时返回 `[status: running]` 后**继续 wait**，直至 `completed`。
  3. 等待期间不做任何其他工作、不结束本轮。
- 若睡眠 job 被中断（killed/失败）：重新计算剩余时间，再起一个新 sleep job 继续等。

### 5. 窗口内自动执行

- 睡眠 job 完成 = 已到窗口起点，立即开始执行任务（工具调用、子代理等正常进行）。
- 任务较长需多轮：每轮结束前检查进度——未完成则结束本轮，由 goal-round-driver 自动续跑下一轮（此时已在空闲窗口内，续跑成本可接受）；完成则执行第 6 步。
- 每轮先复核当前时间确认仍在窗口内；若已出窗口（极端情况），回到第 2-4 步等待下一窗口。

### 6. 收尾

- `get_goal` 取精确 goal_id/revision → `update_goal` action complete。
- 向用户汇报：交付物/结果、实际执行时段、等待时长。

## 注意

- 不要用 `update_goal` 的 pause/resume 实现本技能：pause/resume 需要直接人类回合，agent 无法自动恢复；挂起用 active goal + objective 时间指令 + 轮内睡眠即可。
- 时间窗口默认 12:00-14:00、18:00-次日 09:00（依据 DeepSeek 使用习惯）；用户给其他窗口时按用户口径计算。
- 本技能是"同会话"挂起：若 DSH 进程/会话重启，goal 状态不跨会话保留，用户需在新会话重新触发并描述任务。
