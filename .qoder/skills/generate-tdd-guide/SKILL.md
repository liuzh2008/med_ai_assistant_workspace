# TDD 实施指南生成（Generate TDD Guide）

按敏捷开发和测试驱动开发（TDD）原则，为指定项目生成一份**专业、详细、可操作**的 TDD 实施指南文档。

## 调用方式

| 方式 | 触发条件 |
|------|---------|
| 斜杠手势（DSH Web） | 在 DSH Web 输入框直接输入 `/generate-tdd-guide`（输入 `/` 后会自动弹出技能建议菜单 "Trigger suggestions"，选择本技能即可），回车发送即自动注入技能指令并执行；可附加文本，如 `/generate-tdd-guide 为质控模块生成指南，覆盖率 80%`。此路径为 DSH 内置机制（`skill.list` + pre-step `/name` token 注入），无需额外注册 |
| 斜杠命令（qoder） | 用户输入 `/generate-tdd-guide`（qoder 编辑器，命令定义见 `.qoder\commands\generate_tdd_guide.md`） |
| 自然语言 | 用户说"编写 TDD 实施指南"、"生成测试驱动开发计划"、"写一份 TDD 文档"、"红绿重构计划"等 |
| 场景 | 新模块开工前制定开发计划、迭代规划、质量评审需要测试方案时 |

## 执行流程

### 第一步：收集项目信息（缺失时先询问用户）

| 信息 | 说明 |
|------|------|
| 项目名称 | 必填，用于文档命名与概述 |
| 项目描述 | 项目目标与核心功能，1~3 句 |
| 开发周期 | 预计时间范围（如 2026-08-13 ~ 2026-09-30） |
| 质量目标 | 如"核心模块单元测试覆盖率 ≥ 80%，总覆盖率 ≥ 70%" |
| 模块清单 | 通常 3 个模块，每个模块需可描述其核心功能 |

若用户未指定，默认以当前项目（医疗AI辅助系统 MedAiAssistant：Java 21 + Spring Boot 3.5.8 + Oracle 21c / Vue 3 + Element Plus）为对象生成。

### 第二步：按模板生成

严格按下方「文档模板」生成，**保留全部章节编号与层级**，将占位符替换为实际内容。模板中标注"示例"的片段（如 pytest.ini、Gherkin）为可直接落地的示例代码。

### 第三步：文档命名与保存

- **命名规则（必须完整、准确）**：`TDD实施指南-<项目名称>-<YYYYMMDD>.md`，例如 `TDD实施指南-医疗AI辅助系统-20260813.md`；同一项目的迭代更新追加版本号，如 `TDD实施指南-医疗AI辅助系统-20260813-v2.md`。若为英文环境可命名 `TDD-Implementation-Guide-<ProjectName>-<YYYYMMDD>.md`。
- **保存位置**：默认保存到 `doc\` 目录；用户指定位置时按指定保存。

## 生成要求

- 每条用户故事必须包含：用户角色（作为…）、需求描述（我需要…以便…）、验收标准（Given-When-Then）。
- 每个开发任务必须三阶段齐备：红（失败测试清单）、绿（最小实现方案）、重构（优化方向）。
- 周期表、风险矩阵、质量门禁表、交付计划表等**必须完整填写**，不得留空或写"待补充"。
- ATDD 场景一律使用 Gherkin 语法（Feature / As a / I want / So that / Scenario / Given / When / Then）。
- 若模块信息不足，按 3 个模块生成占位章节并明确提示用户补充，而不是跳过。

### 4. 测试策略

#### 4.1 测试金字塔配置

- 单元测试（70%）：`<框架选择、覆盖范围>`
- 集成测试（20%）：`<集成点、测试场景>`
- E2E 测试（10%）：`<端到端流程>`

技术栈适配示例（本项目默认栈）：

- 后端单元测试：JUnit 5 + Mockito；前端单元测试：Vitest（Vue 组件）。
- 集成测试：Spring Boot Test + Testcontainers（Oracle 21c 容器）验证 DAO/Service 与数据库集成；前端接口联调用 MSW。
- E2E 测试：Cypress，覆盖登录 → 主流程 → 结果落库的关键路径。

#### 4.2 测试环境配置

- 测试框架配置（示例：pytest.ini，使用其他语言时替换为对应框架配置，如 `pom.xml` 的 surefire 配置 / `vitest.config.ts`）：

```ini
[pytest]
testpaths = tests
python_files = test_*.py
addopts = -v --strict-markers --cov=src --cov-report=term-missing --cov-fail-under=70
markers =
    unit: 单元测试
    integration: 集成测试
    e2e: 端到端测试
```

- 测试目录结构：

```
项目根/
├── src/                  # 生产代码
└── tests/
    ├── unit/             # 单元测试（70%）
    ├── integration/      # 集成测试（20%）
    └── e2e/              # E2E 测试（10%）
```

- 持续集成流水线配置（示例：GitHub Actions 关键步骤：checkout → 依赖安装 → 单元测试 → 集成测试 → E2E → 覆盖率上传 → 质量门禁判定）：

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pip install -r requirements-dev.txt
      - run: pytest -m unit
      - run: pytest -m integration
      - run: pytest -m e2e
      - run: coverage report --fail-under=70
```

## 输出示例（节选）

一份 3 模块的指南约 60~120 行正文（不含配置代码）。示例片段：

```gherkin
Scenario: 医生保存诊断结论成功
  Given 医生已登录并完成诊断录入
  When 医生点击"保存诊断结论"
  Then 系统提示保存成功且结论持久化到数据库
```

## 注意事项

- 文档语言：默认简体中文（代码标识符、框架名、命令保留原文）。
- 严格遵循 TDD：先写测试再实现，禁止在绿阶段之前编写生产代码。
- 生成后主动提醒用户：模块清单、覆盖率目标等占位信息是否准确，便于修订。
