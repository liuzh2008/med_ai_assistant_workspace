# 代码审查（Code Review）

## 工作流来源

完整的三阶段强制审查工作流定义在 `.qoder/commands/code-review.md`，**这是唯一的事实来源（Single Source of Truth）**。执行审查时，**必须严格遵循**该文件中定义的流程、检查维度、输出格式和注意事项。

> ⚠️ **禁止在本 SKILL.md 中复制命令文件的工作流内容**。任何流程变更都应直接修改 `.qoder/commands/code-review.md`，本技能文件仅作为注册 `/code-review` 斜杠命令的包装入口。

## 调用方式

| 方式 | 触发条件 |
|------|---------|
| 斜杠命令 | 用户输入 `/code-review` |
| 自然语言 | 用户说"审查一下代码"、"做代码审查"、"review 本次变更"等 |
| 工作流集成 | `bug-fix` 技能修复完成后、`testserver-deploy` 部署前等场景自动触发 |

## 执行概要

技能被调用后，必须按以下流程执行：

### 阶段一：收集信息
获取 git diff、读取修改文件、检查相关测试、补充上下文。
→ 完整步骤见 `.qoder/commands/code-review.md#阶段一收集信息`

### 阶段二：逐项审查
从核心逻辑、安全合规（重点）、代码整洁、性能与资源、周边配套五个维度系统评估。
→ 完整检查项见 `.qoder/commands/code-review.md#阶段二逐项审查`

### 阶段三：输出审查报告（主代理执行，不得跳过）
将结构化审查报告保存到 `med_ai_assistant_1.0_bs_backend\doc\代码审查\{yyyy-MM-dd}-{审查主题}.md`。
→ 完整输出格式见 `.qoder/commands/code-review.md#阶段三输出审查报告主代理执行不得跳过`

## 职责分配

- **阶段一和阶段二**：可以委托给系统内置的 `CodeReview` 子代理（`Agent` 工具 → `subagent_type: "CodeReview"`）执行
- **阶段三**：**必须由主代理（当前 agent）亲自执行**，不得委派给任何子代理

## 质量门禁

| 检查项 | 要求 |
|--------|------|
| 审查依据 | 基于最新 `git diff`，不得凭空审查 |
| 临时文件 | 禁止创建 `review_diff.txt` 等临时文件存储 diff |
| 结论明确 | 必须给出「通过 / 有条件通过 / 不通过」之一 |
| 问题可追溯 | 问题清单中的文件路径应可直接定位（如 `xxx.java:25`） |
| 报告归档 | 审查报告必须保存到 `doc\代码审查` 目录 |
| 安全合规 | JWT 公开路径放行、UTF-8 编码、API 入参校验、PII 泄露是审查重点 |
