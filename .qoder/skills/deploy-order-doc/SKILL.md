# 部署说明文档生成（固定五步顺序）

本技能只做一件事：**把一次上线"按固定顺序"写成一份可以直接照着做的《部署说明》**。
它不发明部署方式——命令细节来自 `aimedteach-deploy` / `testserver-deploy` / `testserver-pull-deploy` / `ssh-testserver` 等既有技能与仓库内 `deploy/` 目录；本技能负责**顺序、完整性、可执行性与落盘规范**。

## 一、何时用

- 用户说"写部署说明 / 生成部署文档 / 上线操作单 / 这次上线要做什么"；
- 一次发布需要**跨环境**（测试服 + 医院生产）或**跨组件**（后端 + 前端 + 数据库）时；
- 需要留档"谁在什么时间按什么顺序做了什么、怎么回滚"时。

**不做什么**：不替代具体部署技能的执行步骤；不在文档里写生产密钥；不把测试服地址当生产地址。

## 二、固定顺序（**不得调换**）

> 顺序的理由：先"只读体检"确认库和版本现状（避免带病上线），再处理不可逆的数据库变更（越早越好，且失败可停在干净状态），然后后端（新接口就位）、前端（界面就位），最后才让用户接触（验收）。**前端先行会导致"界面已上线但接口 404"的假故障**。

| 步 | 阶段 | 必须产出 | 失败时停在哪 |
|---|---|---|---|
| 1 | **只读体检** | 版本/产物核对 + 数据库只读查询结果 + 容器与端口现状 | 就地停，不改任何东西 |
| 2 | **数据库变更**（仅当缺表缺列） | 幂等脚本执行记录 + 只读回验 | 停在第 2 步，回滚 DDL 或保持未变更 |
| 3 | **后端部署** | 镜像/包替换 + `/api/health` 200 + version 匹配 | 回退上一镜像，前端不动 |
| 4 | **前端部署** | 包替换 + `version.txt` 匹配 + 首页 200 | 回退旧 `dist`/旧镜像，后端保留 |
| 5 | **功能验收** | 按业务的"点到点"走查记录（截图或场次号） | 不回滚，先修数据/重跑执行 |

## 三、输出契约（硬性）

| 项 | 规则 |
|---|---|
| 目录 | 工作区根目录 `doc/部署说明/`（不存在则创建） |
| 文件名 | `部署说明<YYYY-MM-DD>-<HHmm>.md`，例：`部署说明2026-10-18-1552.md` |
| 时间 | 取**生成时刻**，时区 `Asia/Shanghai`；同分钟重复生成则加 `-2`、`-3` |
| 编码 | UTF-8 无 BOM（用 `write` 工具，不经 shell 重定向） |
| 长度 | 以"能照着做"为准；命令一律可复制，禁止"略" |
| 提交 | 生成后按项目规则本地 commit（`docs(部署说明): …`），不 push 除非用户要求 |

## 四、文档骨架（章节顺序 = 五步顺序）

```markdown
# 部署说明：<一句话主题>

## 0. 元信息           目标环境 / 版本跨度 / 变更内容 / 影响面 / 停机窗口 / 执行人 / 回滚负责人
## 1. 前置检查（只读，不改任何东西）
   1.1 版本与产物核对   本地版本、镜像版本、包时间戳
   1.2 数据库只读体检   表/序列/索引存在性、列长度、关键数据量
   1.3 环境现状         容器状态、端口占用、磁盘余量、时区
## 2. 数据库变更（若无变更，写"本次无需变更"并给出判定依据）
   2.1 是否需要变更     判定语句 + 期望值
   2.2 执行            脚本路径 / 执行方式（sqlplus 版 vs 图形客户端版）/ 幂等性说明
   2.3 回验            只读查询 + 期望输出
   2.4 回滚            DROP/还原语句 + 影响面（会丢什么）
## 3. 后端部署
   3.1 上机前的包清单   文件名 + 大小 + 生成时间
   3.2 上传             scp/cp 命令 + 目标目录 + 权限
   3.3 执行             deploy 脚本 + 期望输出关键字
   3.4 验证             health / version / 日志判据
## 4. 前端部署
   4.1 包清单  4.2 上传（root 目录需 sudo）  4.3 执行（deploy-from-package.sh）  4.4 验证（version.txt / 首页 200 / 资源可下载）
## 5. 功能验收         按用户真实操作路径逐条列，每条写"操作 → 期望"
## 6. 回滚预案         前端 / 后端 / 数据库 三段各自命令，按"先回前端还是先回后端"给建议
## 7. 风险与注意事项   停机窗口、幂等边界、易错操作（禁止覆盖 .env、禁止清库）
## 8. 执行记录         打勾表：步骤 / 执行人 / 时间 / 结果 / 备注
## 附录 A 包与脚本校验和     附录 B 常见报错对照（现象 → 原因 → 处置）
```

## 五、事实来源（**先读，禁止编造**）

写文档前必须从仓库取到以下事实，逐条落到文档里：

| 事实 | 取值位置 |
|---|---|
| 前端/后端版本 | `med-teach-frontend/package.json`、`med-teach-backend/pom.xml` 的 `<revision>` |
| 部署包与脚本 | `med-teach-*/deploy/<env>/`（`wuyiyuan` 生产 / `testServer` 测试） |
| 升级脚本包 | `med-teach-backend/deploy/<env>/sql/upgrade-<版本>/`（含 `README.md`、`00-check-*.sql`） |
| 生产路径 | 目标机实际路径以 `docker inspect <容器> --format '{{index .Config.Labels "com.docker.compose.project.working_dir"}}'` 为准 |
| 端口 | 前端 8085 / 后端 8083 / 主系统 8081 / 执行服务器 8082 / Oracle 1521 |
| 验证脚本 | `med-teach-frontend/e2e/*.mjs`（在服务器上 `node` 跑） |

**每条命令都要标"在哪台机器执行"**（本机 Windows / 测试服 / 医院跳板机 / 数据库客户端）。

## 六、质量红线

1. **不写生产密钥**：文档中一律写 `<见 .env>`，且明确"**上传时不要覆盖 `.env`**"。
2. **SQL 必须标只读或幂等**；含 `DELETE/UPDATE` 的脚本要给"先 SELECT 同条件预览"。
3. **不把测试服当生产**：两个环境的地址/KEY/路径不得混写。
4. **每条验证都要有期望输出**（状态码、版本号、`healthy`、行数）。
5. **不写"如果失败就看日志"**这种空话，要给出**具体命令 + 该找的关键字**（如 `ORA-00942`、`UnsatisfiedDependencyException`、`upstream`）。
6. **不承诺未验证的能力**：文档里出现"已验证"字样的，必须能指到一次真实执行记录（时间/输出）。

## 七、生成后自检（逐条打勾）

- [ ] 文件已落盘 `doc/部署说明/部署说明<日期>-<时间>.md`，UTF-8 无 BOM
- [ ] 五步顺序齐全，没有把前端排在后端之前
- [ ] "数据库变更"章节要么给出判定 SQL + 结论，要么明确写"本次无变更"并说明依据
- [ ] 每条命令都写了执行机器、路径、期望输出
- [ ] 回滚三段（前端/后端/数据库）齐备
- [ ] 文档中提到的每个包/脚本路径在本仓库**实际存在**（用 `glob`/`Test-Path` 核对）
- [ ] 版本号与 `package.json` / `pom.xml` 一致
- [ ] 已本地 commit

## 八、与其他技能的关系

| 技能 | 分工 |
|---|---|
| `aimedteach-deploy` | 提供 AIMedTeach 测试服/五医院的**具体构建、打包、上传、部署命令**与坑位 |
| `testserver-deploy` / `testserver-pull-deploy` | 测试服开发模式与主系统部署 |
| `ssh-testserver` | 连接信息与远程排障 |
| **本技能** | 只负责**按固定顺序把上述事实编排成可执行、可回滚、可留档的《部署说明》** |
