## 示例二：技术问题 — 打破"问题一~六"编号

### 改造前
```
**所要解决的技术问题按重要性排序：**

**问题一**：AI生成教案的医学准确性问题——需构建独立的生成AI...
**问题二**：审查标准的结构化问题——需建立三维度...
**问题三**：审查到优化的自动化衔接问题——需建立自动定向优化机制...
**问题四**：Prompt模板的管理问题——需建立数据库驱动的引擎...
**问题五**：审查标准的自适应问题——需建立学情层次感知机制...
**问题六**：优化的粒度控制问题——需建立约束机制...
```

### 改造后（合并为 3 个自然段落）
```
LLM生成教案面临的首要难题是医学准确性与教学规范性的双重保障。
现有方案中，生成和审查通常共用同一AI模型，本质上是让模型"自我审查"...
本发明提出构建独立的生成AI与审查AI双角色架构...
与此配套，还需建立三维度的结构化审查评分体系...

审查发现问题之后的自动修复构成了第二个技术难点。
现有流程要求教师对照审查报告手动逐条修改教案，效率低下且容易遗漏。
本发明引入优化AI角色...这里需要解决两个子问题：一是粒度控制...二是衔接效率...

在基础设施层面，Prompt模板的管理方式直接影响系统的可维护性和审查质量。
传统做法将模板硬编码在代码中...本发明采用数据库驱动的Prompt模板管理引擎...
此外，审查标准需要随目标学员层级动态调整...
```

## 示例三：有益效果 — 打破"效果一~八"并多样化句式

### 改造前（8条，全部以"通过…实现…"开头）
```
**效果一：通过AI双角色独立架构实现交叉验证，根本性解决"自我审查"盲区。** ...
**效果二：通过三维度结构化审查评分体系，实现审查报告的机器可消费...** ...
**效果三：通过"仅修正扣分项"的定向优化约束，实现精准修改...** ...
**效果四：通过学情层次感知的自适应审查标准，实现差异化质量评判。** ...
**效果五：通过数据库驱动的Prompt模板引擎，实现模板的热更新...** ...
**效果六：通过管线三级容错降级策略，确保系统鲁棒性...** ...
**效果七：通过SSE流式进度推送，实现三阶段管线的实时可见性。** ...
**效果八：通过双角色架构的跨场景复用设计，实现质量保障体系统一。** ...
```

### 改造后（5条，五种不同的句式开头）
```
第一，双角色交叉验证消除了单模型自我审查的盲区。生成AI和审查AI各自加载
独立的Prompt模板，在互不共享调用上下文的前提下分别以"资深教育专家"和
"严格质控专家"的身份进行推理。审查AI以批判式视角审视生成AI的输出...
（结果前置）

第二，优化AI采用定向修正而非完全重写的策略，保住了教师原有的教学意图。
优化Prompt中嵌入了五大约束指令：只能修改审查报告指出的扣分项...
教师通过终审界面中初版与优化版的对比视图，可逐项查看每一处改动...
（策略描述）

第三，审查标准根据目标学员层级自适应调整。审查AI从Prompt中的
{{targetAudience}}变量感知学情层次，动态切换各维度的评判尺度...
（机制描述）

第四，数据库驱动的Prompt模板引擎使模板修改不再依赖应用重新部署。
模板通过IS_ACTIVE字段控制灰度切换，VERSION字段记录版本演进...
配合SSE流式进度推送和三级容错降级策略...系统在异常场景下仍能向教师
交付可用的教案。所有失败场景均不回滚已保存的中间数据。
（工具主语 + 合并原效果五/六/七）

第五，该双角色架构具备跨场景的复用能力。教案生成、题目命制和讨论提纲
生成三类场景共用同一套"生成—审查—优化"管线，仅需替换对应的Prompt模板
即可实现质量闭环...
（属性陈述 + 原效果八）
```
