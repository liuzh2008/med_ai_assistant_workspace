# 计划追问审查

## 概述

对一个计划、方案或设计进行系统性追问审查，直到每个决策点都有明确的答案。适用于方案评审、技术设计审查等需要消除模糊性的场景。

## 执行步骤

### 步骤一：审查计划

阅读待审查的计划，识别以下类型的模糊点：

1. **未明确的决策**：哪些地方用了"可能"、"或者"、"待定"等模糊词
2. **未覆盖的场景**：正常流程之外的边界情况和异常处理
3. **未量化的指标**：性能、容量、可用性等未给出具体数字
4. **未指定的方案**：多个候选方案未说明选择理由
5. **未评估的风险**：可能的风险点未被识别

### 步骤二：逐项追问

针对每个模糊点进行追问，直到获得明确的答案：

**追问维度清单**：

| 维度 | 追问示例 |
|------|---------|
| **目标** | "这个功能的成功标准是什么？如何度量？" |
| **方案选择** | "为什么选 A 而不是 B？两者的权衡是什么？" |
| **边界条件** | "输入为空/无效时怎么处理？并发冲突怎么办？" |
| **性能** | "预期的 QPS 是多少？响应时间要求是？" |
| **依赖** | "这个模块依赖哪些外部服务？如果依赖不可用怎么办？" |
| **安全** | "哪些数据需要加密？权限控制怎么做？" |
| **回退** | "如果上线后发现问题，回退方案是什么？" |
| **测试** | "如何验证这个功能正确？测试策略是什么？" |

### 步骤三：确认完整

检查以下问题列表，确保全部已回答：

- [ ] 所有"待定"项已明确
- [ ] 所有候选方案已有选择理由
- [ ] 性能指标已量化
- [ ] 异常处理已覆盖
- [ ] 风险已识别并评估
- [ ] 回退方案已制定
- [ ] 验收标准已定义

## 输出

```markdown
## 追问审查结果

### 已明确的决策
| 原模糊点 | 追问后结论 |
|---------|-----------|
| [模糊点1] | [明确结论] |

### 仍待解决的问题
| 问题 | 需要谁决策 |
|-----|-----------|
| - | - |（如全部解决则填"无"）

### 审查结论
- **方案成熟度**：[高/中/低]
- **是否可进入下一阶段**：[是/否]
```
