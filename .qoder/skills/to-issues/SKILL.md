# 计划拆分为 Issues

## 概述

将 PRD、方案文档或开发计划，按**垂直切片**（端到端功能，而非前端/后端/数据库等分层）拆分为可独立处理的 GitHub Issues。

## 垂直切片原则

**正确拆分方式**（垂直切片）：
```
✅ Issue 1: 用户登录功能（前端表单 + 后端 API + 数据库表）
✅ Issue 2: 用户注册功能（前端表单 + 后端 API + 数据库表）
```

**错误拆分方式**（水平分层）：
```
❌ Issue 1: 前端页面开发
❌ Issue 2: 后端 API 开发
❌ Issue 3: 数据库表创建
```

## 执行步骤

### 步骤一：审查输入

审查待拆分的 PRD/计划/方案文档，识别以下信息：
1. 功能列表：有哪些独立的功能点
2. 依赖关系：功能之间的先后依赖
3. 优先级：哪些功能是 P0/P1/P2
4. 工作量估算：每个功能的预估工作量

### 步骤二：垂直切片拆分

将功能按垂直切片拆分，每个切片应包含：

| Issue | 垂直切片 | 包含内容 | 预估工时 | 依赖 |
|-------|---------|---------|---------|------|
| #1 | [功能名] | 前端+后端+DB | [时间] | 无 |
| #2 | [功能名] | 前端+后端+DB | [时间] | #1 |

### 步骤三：生成 Issue

为每个垂直切片创建一个 GitHub Issue：

```markdown
## Issue 标题：[功能名称]

### 功能描述
[一句话说明]

### 验收标准
- [ ] [标准1]
- [ ] [标准2]

### 技术要点
- [要点1]
- [要点2]

### 依赖
- 依赖 Issue：#[编号]
- 被依赖：#[编号]

### 预估工时
[时间]
```

### 步骤四：关联与标签

1. 将 Issue 添加到 GitHub Project（如有）
2. 添加标签：`vertical-slice`, `feature`, 优先级标签
3. 在 PRD Issue 中引用所有拆分后的子 Issue

## 输出

```markdown
## 拆分结果
| Issue | 功能 | 预估工时 | 依赖 |
|-------|------|---------|------|
| #[编号] | [功能名] | [时间] | 无 |
| #[编号] | [功能名] | [时间] | #[编号] |
```
