# 文书时限监控（Time Limit Monitor）

## 适用场景 / 触发条件

- 医生问"这个患者今天该写什么""首程/入院记录快超时了吗"（流程步骤 #32）；
- 病情告知/知情同意待办提醒（#16）：重大检查/治疗前需签署同意书，提醒未签项；
- 文书时限超时质控：8h/24h/48h/72h/3 日等时限自动提醒，避免质控扣分。

## 执行步骤（编号）

1. **患者锚定**：调用 `medai_patient_list_by_department` / `medai_patient_basic_info` 确认患者（或按科室拉取在院清单逐患者扫描），`medai_patient_flow_status` 获取入院时间与当前阶段。
2. **时限规则引用**（规则源=《住院部医生日常工作流程》§3 时限表，配置在 Java/DB，agent 只引用不持有）：
   - 首次病程记录：入院 **8 小时**内；
   - 入院记录：入院 **24 小时**内；
   - 主治医师首次查房记录：**48 小时**内；
   - 主任/副主任医师首次查房记录：**72 小时**内；
   - 日常病程：病危≥1 次/日、病重≥1 次/2 日、稳定≥1 次/3 日；
   - 手术记录：术后 **24 小时**内；术后病程：连续 3 天每日记录；
   - 常规会诊：**48 小时**内完成；急会诊：**10 分钟**到场；
   - 抢救记录：抢救结束 **6 小时**内补记；
   - 出院小结：出院后 **24 小时**内。
3. **待办计算**：调用 `medai_due_documents`（未来工具）按时限规则计算"今日到期/已超时"文书清单（剩余时间/超时小时数），已超时项排在到期项之前；同时核对该患者病情告知/知情同意未签待办（#16）。
4. **文书已写状态核对**：调用 `medai_medical_records` 核对时限项文书是否已生成（避免对已写文书重复提醒）；未写的到期/超时项明确列出。
5. **提醒呈现**：按"已超时 > 今日到期 > 即将到期"排序呈现，引用具体时限（如"首次病程记录：剩余 2 小时"）；超时项标注红色警示，并给出补写入口（联动对应剧本：入院文书→admission-record、查房→ward-round、手术→preop-discussion、出院→discharge-summary）。

## 文书格式要点

- 提醒清单结构：**文书名称 → 时限要求 → 状态（已超时 X 小时/剩余 X 小时/已按时完成）**；
- 时限从入院/术后/接报等锚点时刻起算，agent 展示锚点时间便于医生核对；
- 超时项必须醒目置顶，不淹没在清单中。

## 审核与保存要求

- 时限监控为**只读提醒**，不生成文书、不写库；
- 补写文书走对应剧本（草稿→医生审核→审批落库），agent 不代写正式文书；
- 知情同意待办仅提醒，签字是人的行为（不介入）。

## 注意事项（脱敏/患者锚定）

- 时限数值以系统配置（Java/DB）为准，agent 展示的规则表仅作参照，规则更新由后端下发；
- 逐患者扫描时确认患者范围不跨科室；展示用脱敏标签；
- 已超时提醒要准确到小时，不用模糊表述；数据缺失时如实说明，不编造时限状态。
