## 三、更新流程总览（四步）

```
1 提交与版本  →  2 构建  →  3 投放  →  4 部署与验证
```

1. **提交**：根仓库 + backend 子模块 + vue 子模块分别提交；`bump-version.ps1` 升版本；`doc/部署清单.md` 登记。
2. **构建**：
   - 后端主：`mvn package -DskipTests` → `docker build -t med-ai-main` → `docker save`
   - 后端执行：`mvn package -DskipTests` → `docker build -f deploy/execution-linux/Dockerfile.execution.linux -t med-ai-execution`
   - 前端：`npm run build` → 校验 `dist/index.html` + `dist/js/app.*.js` → 复制到 deploy 包 → `docker build` → `docker save`
3. **投放**：tar/zip 拷到目标服务器（手动路径）或放到构建服务器 `/medai/build-files`（自动路径）。
4. **部署**：目标机执行 `deploy.sh` / `deploy-linux.sh`，或等 systemd 定时任务自动执行。

9. 健康检查：`8081/api/health`、`8082/api/execute/health`、`8080/api/health`。

**手动触发**（等同）：登录服务器


```bash
# 主服务器

# 执行服务器
scp -r med_ai_assistant_1.0_bs_backend/deploy/execution-linux root@10.120.10.251:/root/docker/
# 前端（在 vue 仓库目录下执行）
scp -r med_ai_assistant_1.0_bs_vue/deploy/med_ai_assistant_1.0_bs_vue root@10.120.11.43:/root/docker/
```

目标机部署：

```bash
# 主服务器：加载镜像 → 同步配置 → compose 启动 → 健康检查（8 步）
cd /root/docker/main-linux-oracle && ./deploy.sh
# 执行服务器（5 步）
cd /root/docker/execution-linux && ./deploy.sh
# 前端
cd /root/docker/med_ai_assistant_1.0_bs_vue && chmod +x deploy-linux.sh && ./deploy-linux.sh
```

`deploy.sh` 内部动作（主服务器）：
`检查 docker/compose → 建 config/logs/temp 目录 → 若旧镜像存在先 down + rmi → docker load med-ai-main.tar → 从镜像提取默认配置补全 config/application.properties → compose -p medai-main-prod up -d --force-recreate → 健康检查 8081`。

#### 4.2.2 自动路径（systemd 定时，02:30–03:30 安全窗口）

| 机器 | 脚本 | 触发 | 数据源 |
|---|---|---|---|
| 主服务器 | `auto-deploy-all.sh` → `auto-deploy-backend.sh` + `auto-deploy-frontend.sh` | `install-auto-deploy-timer.sh` 装 systemd timer（默认 02:35，RandomizedDelaySec=180） | 本机 `/api/deploy/latest` → 构建服务器 `10.120.10.251:8082/api/build-files/...` |
| 执行服务器 | `auto-deploy-execution.sh` | 独立 timer（`install-auto-deploy-execution-timer.sh`） | 本机 `8082/api/build-files/latest` → 构建服务器下载 tar |

主服务器自动部署的 10 个动作：
1. 校验安全窗口（02:30–03:30，`DEPLOY_ALLOW_OUTSIDE_WINDOW=true` 可绕过）；
2. `GET /api/deploy/latest` 取最新 backend 版本；
3. 与 `version.txt` / 镜像 label 比对，相同且 tar 已在则跳过（`FORCE_REDEPLOY=true` 强制）；
4. 下载 `med_ai_assistant_backend-<ver>.tar` + manifest + deploy-package zip（支持断点续传）；
5. 用 manifest 校验 tar（SHA256）；
6. 备份当前部署目录（`<dir>.backup.yyyyMMdd_HHMMSS`，含旧镜像）；
7. 保留 `config/`、`.env.main`、compose 文件等，清空其余；
8. 合并新包中的 `config/application.properties` 与 `.env.main`（**只增缺失键，不覆盖已有值**）；
9. 执行 `deploy.sh`；失败 → 用备份整体回滚并重新 `deploy.sh`；
10. 执行服务器在部署完成后回调主服务器 `POST /api/deploy/apply`（触发主服务器部署，形成「先执行、后主服务器」的顺序）。

> 自动链路依赖构建服务器上存在约定命名的产物；仓库内**没有**生成这些文件的脚本（见 §七-2）。

## 七、代码检查发现的问题（按严重度）

1. **构建产物投放环节没有脚本化**（高）
   `auto-deploy-*.sh` 需要 `med_ai_assistant_backend-<ver>.tar` / `..._execution-<ver>.tar` / `..._frontend-<ver>.zip` 和 manifest，但仓库内**没有任何脚本生成或上传这些文件**；`build-and-export*.bat` 产出的是 `med-ai-main.tar` / `med-ai-execution.tar`。→ 自动链路目前依赖人工按命名规则制作并放到构建服务器 `/medai/build-files`，容易断。

2. **两套产物命名并存且无对照说明**（高）
   手动用 `med-ai-main.tar`，自动用 `med_ai_assistant_backend-<ver>.tar`；前端本地包叫 `med_ai_assistant_1.0_bs_vue.zip`，CI 打的是 `med_ai_assistant_frontend-<ver>.zip`。新人有极大概率拿错包。

3. **CI 只覆盖前端**（中）
   `.github/workflows/release-frontend.yml` 在打 `v*` tag 时构建前端并发布到 `liuzh2008/medai-builds`；**后端没有任何 CI**，后端产物全靠本地构建。

4. **Gitee 环境下 GitHub release 兜底必然失败**（中）
   `auto-deploy-execution.sh` / `auto-deploy-backend.sh` 的 GitHub 兜底写死 `liuzh2008/medai-builds`，而执行服务器 `git.provider=gitee`、`GitHubReleaseClient` 的 owner/repo 在 Gitee 上不存在（实测 404）→ 兜底路径只会拖慢失败，不能作为真实后备。

5. **测试服务器 `git-poll-deploy.sh` 的 compose up 无超时保护**（中）
   历史上有过挂起 10 分钟 → 脚本中断 → 执行服务器漏更的事故（2026-08-24），脚本至今未加 `timeout`。

6. **前端 nginx.conf 两份分叉**（低，已告警）
   `med_ai_assistant_1.0_bs_vue/nginx.conf` 与 `deploy/med_ai_assistant_1.0_bs_vue/nginx.conf` 内容不同，**随包生效的是 deploy 那份**；`build-and-package.bat` 已加 SHA256 差异告警，但未合并。

7. **`deploy/README.md` 目录清单过时**（低）
   只列了 `main-linux-oracle / main-windows / execution-windows`，实际有 10 个目录（含 execution-linux、testServer、yanting 等），新人按 README 找路径会找不到。

8. **测试服执行服务器用的目录不是 `execution-linux-test`**（低，易踩）
   `git-poll-deploy.sh` 指向 `deploy/execution-linux`（compose 项目 `execution-linux`），`execution-linux-test` 目录是历史遗留；改配置要改前者。
