## 一、链路考古（改代码前先建事实基线）

AI 输出 → 结构化诊断列表的解析调用点共 **5 处**：

| # | 位置 | 用途 | 是否接入护栏 |
|---|---|---|---|
| 1 | `components/patient/AIDiagnosisAnalysisTab.vue` `syncDiagnosisToStore()` | Gate 1 主路径，写 `store.aiDiagnosis` | ✅（主入口） |
| 2 | `components/ai/DiagnosisEditPanel.vue` `diagnosisBlocks` getter | 医生实际看到的诊断面板（行绑定/详情） | ✅ |
| 3 | `components/ai/AIResults.vue` `_initDiagnosisData()` | 另一条写 `store.aiDiagnosis` 的路径 | ✅ |
| 4 | `views/PatientProfileView.vue` | 患者页 AI 诊断块展示 | ✅ |
| 5 | `utils/qualityGate.js` | **Gate 契约校验** | ❌ **不接入（有意）** |

**为什么第 5 处不接入**：契约校验必须基于**原始输出**判定——若先过滤再校验，等于"自己改完答案再判卷"，会把真实的模型缺陷掩盖掉（违反 §四 红线 1 的可观测性）。护栏只作用于**展示与业务写入**路径。

**插入点**：`extractDiagnosisBlocks()` 之后、写入 store / 计算行绑定之前。原始 Markdown（`resultContent` / `aiDiagnosisContent`）**始终保持原样**，可随时追溯。

## 二、护栏规格（`src/utils/diagnosisGuard.mjs`）

### 2.1 判据

| 步骤 | 判据 | 动作 |
|---|---|---|
| 语义去重 | ① 完全同名；② **去括注后同名**（部位标记一致） | 保留 1 条，其余丢弃（`reason=duplicate`） |
| 禁止清单 | 名称以「正常 / 阴性 / 无异常」结尾；含方法学括注（干化学/沉渣/镜检…）；以数值型结果结尾（`2+`、`+-`、`1.025`、`12.3mmol/L`） | 仅对 `category=补充诊断` 的条目丢弃（`reason=lab_line`） |
| 异常告警 | 条目数 > 40；或 > 输入【目前诊断】条目数 × 3 | `warnings`（不删，不静默） |
| 软提示 | 名称以「升高/降低/阳性」结尾（可能对应可命名状态，模板允许保留） | 仅 `warnings`，**不删** |
| 防呆 | 过滤后条目为 0 | **回退为原样展示** + 告警（宁可展示也不清空医生的列表） |

### 2.2 安全边界（红线）

1. **输入条目零丢失**：`category` 为「原诊断 / 修正诊断」的条目**绝不被过滤**；类别缺失时**保守视为受保护**。同一语义若同时存在原诊断与补充诊断，**优先保留原诊断那条**。
2. **零误动优先**：判不准的只告警。典型——同一实体不同部位（「肾囊肿（左肾）」与「肾囊肿（右肾）」）**不得**判为重复（`dedupKey` 保留括注中的部位/侧别标记）；「冠状动脉粥样硬化」与「冠状动脉粥样硬化性心脏病」**不得**判为重复（不做包含关系判定）。
3. **解析链零破坏**：入参与出参同为诊断块数组，只减少条目，不改字段与结构。
4. **留痕**：所有丢弃项在 `dropped` 中给出名称、原编号、原因、保留项编号；`describeGuardResult()` 生成给医生看的一句话。
5. **幂等**：重复调用结果不变（已测）。

> 开发过程中的一次自我纠正：`NUMERIC_RESULT_END` 最初包含"纯整数结尾"分支，会把「高血压病3级」「2型糖尿病」这类合法名称误判为检验结果条目（单测当场暴露）→ 已收窄为"带单位 / 带小数点 / 带 `+`"三类。

## 三、真实组件树与接入位置

```
患者页   ：PatientTabs.vue ─(tab 'ai-diagnosis')→ AIDiagnosisTab.vue → AIDiagnosisAnalysisTab.vue ─┐
AI 辅助页：AIView → AITabs.vue → AIResults.vue ─────────────────────────────────────────────────────┤
                                                                                                    └→ DiagnosisEditPanel.vue（两条路径共用）
```

**为什么先查组件树**：最初只在 `AIDiagnosisAnalysisTab.vue` 接入并挂提示条；查引用后发现该组件只是**患者页的一条路径**，而 AI 辅助页走 `AIResults.vue → DiagnosisEditPanel.vue`，那条路径会**静默过滤**（违反 §三 禁止项 6"不得静默降级"）。据此把提示条统一收到**两条路径共用的 `DiagnosisEditPanel.vue`**，`AIDiagnosisAnalysisTab` 只做归一化、不再单独提示（避免同一页面出现两条提示）。

最终接入：

| 位置 | 作用 | 是否出提示 |
|---|---|---|
| `DiagnosisEditPanel.vue` | 共用面板；computed `_guardResult` 为**单一计算源**，`diagnosisBlocks`（列表）与 `guardReport`（留痕）同源，保证"提示与列表一致" | ✅ `el-alert.guard-alert` |
| `AIDiagnosisAnalysisTab.vue` | 写 `store.aiDiagnosis` 前归一化 | ❌（由共用面板展示） |
| `AIResults.vue` | 写 `store.aiDiagnosis` 前归一化 | ❌（同上） |
| `PatientProfileView.vue` | 诊断说明 Popover 的块列表 | ❌（次要展示） |
| `qualityGate.js` | **有意不接入**：契约校验必须看原始输出 | — |

## 五、明确不做的事（避免过度归一化）

1. **不做包含关系/模糊合判**：「冠状动脉粥样硬化」与「冠状动脉粥样硬化性心脏病」是不同诊断，模糊合并会制造漏诊风险；
2. **不删「升高/降低/阳性」类**（如「转氨酶升高」模板明确允许保留）→ 只告警，交由模板与医生判断；
3. **不改 `qualityGate.js` 与 `diagnosisParser.js`**：前者需看原始输出，后者应保持纯解析；
4. **不改后端/不改库表**：本次为纯前端展示层归一化，**零 DDL、零数据写入**。

### 页面级 E2E 的障碍（如实记录，非护栏缺陷）

Cypress 在测试服的推进与卡点：

1. 缺 `Xvfb` → 已补装，Cypress 可运行 ✅；
2. **登录**：真实登录成功（`POST /api/users/login` 200），但停在「医疗AI助手服务协议」弹窗 —— 原因是条件判断取的是**即时快照**，弹窗尚未渲染即判定"无按钮"而跳过点击 → 改为先 `cy.wait` 再判断 ✅；
3. **患者页导航**：直接 `cy.visit('/patient-profile/:id')` 时 store 无 `currentPatient`，页面显示"暂无病人数据，请先选择病人"；改用 SPA 内 `router.push` 渲染出的也只是病人基本信息区 —— 该应用的导航设计**要求先经患者列表选中患者**；
4. **患者列表定位**：试图用 `cy.intercept` 把列表 API 过滤为仅目标患者，实测 `patientRows=64` → **拦截未命中该列表的数据源**（列表数据来自与本假设不同的接口/响应结构），因此点击到的不是目标患者。

**结论**：页面级断言卡在"如何在 E2E 中把特定患者放进 `currentPatient`"，属**测试脚手架**问题。护栏正确性已由四层证据覆盖（真实数据净效果 / 26 项单测 / 构建产物含代码 / 容器部署成功）。探针 spec **未入库**（避免留下不通过或用无断言"假通过"的用例）。

**若后续要补齐该 E2E**：先确认患者列表的实际数据源接口，或由前端提供"按 patientId 直达患者页"的测试入口（当前无此入口）。
