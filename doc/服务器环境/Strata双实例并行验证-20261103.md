# Strata 双实例并行验证报告

**日期**：2026-11-03
**目的**：验证同一台机器能否同时运行两个 Strata 服务实例，为"NVIDIA + AMD 双卡"方案（5070 + R9700）排除软件机制风险
**结论**：**通过。两个实例可同时加载、各自推理、并发互不干扰。**

---

## 一、结论摘要

| # | 验证项 | 结果 |
|---|---|---|
| 1 | 两个 Strata 进程同时存活 | ✅ PID 226000（:5080）、226015（:5081） |
| 2 | 两个端口都返回 `loaded: true` | ✅ |
| 3 | 两个实例各自能完成推理 | ✅ 各返回 80 tokens |
| 4 | 并发请求互不阻塞 | ✅ 同时发两个请求，6.3 秒都完成 |

**额外发现**：同一张 32 GB 卡上跑两个实例也能成功——引擎会**动态压缩 expert cache** 直到装得下（A 从 8.72 GiB、B 从 10.55 GiB 开始，最终显存占满 31.9/31.9 GiB，两个都 ready）。

## 三、验证步骤

### 3.1 安装 Linux HIP 引擎（615 MB）

```bash
# 官方 feed 走 GitHub 会超时，用镜像
URL="https://gh-proxy.com/https://github.com/Niko1221/Strata/releases/latest/download/strata-engine-0.1.56-linux-x86_64-hip-rx9070.tar.gz"
curl -L --max-time 900 -sS -o /data/strata-engine-0.1.56-linux-x86_64-hip-rx9070.tar.gz "$URL"
# 25 秒，616 MB

# 安装（签名校验 + 试启动）
export STRATA_DATA_DIR=/data/strata
cd /data/strata/terminal/0.1.56
./bin/strata components install-file /data/strata-engine-0.1.56-linux-x86_64-hip-rx9070.tar.gz
```

输出：

```
Unpacking the engine file
Checking the package signature and every file
Test-starting engine 0.1.56 linux-x86_64-hip-rx9070 before switching to it
Switching to engine 0.1.56 linux-x86_64-hip-rx9070
Engine 0.1.56 is installed and will be used on the next start
```

> **要点**：`install-file` 不联网、校验 SHA-256 + 签名，比 `strata update` 可靠（后者走官方 feed 会被墙）。

### 3.2 两份独立配置

**关键**：每个实例要有独立的 `port`、`log`，并用 `--resident-budget-gib` 限制内存。

配置 A（`/data/strata/q2_0-a.json`）：

```json
{
 "exe": "component:strata-engine",
 "args": [
  "--pack", "/mnt/win-data/Strata/Models/packs/q2_0",
  "--native", "/mnt/win-data/Strata/Models/models/Q2_0/...-00001-of-00002.gguf",
  "--ple-gguf", "/mnt/win-data/Strata/Models/models/Q2_0/...-00002-of-00002.gguf",
  "--ple-io", "mmap",
  "--expert-profile", "/data/strata/terminal/0.1.56/data/expert-profile.bin",
  "--expert-cache", "8192",
  "--prefill", "auto:4096",
  "--spec", "4", "--spec-min-p", "0.5",
  "--mtp", "/mnt/win-data/Strata/Models/mtp/rt",
  "--max-context", "32768",
  "--kv", "int8", "--kv-resident", "16384",
  "--pool-workers", "8",
  "--vram-reserve-mib", "1000",
  "--resident-budget-gib", "14",
  "--conversation-cache-mib", "1024",
  "--conversation-cache-slots", "2"
 ],
 "cwd": "/data/strata/terminal/0.1.56",
 "tokenizer": "/mnt/win-data/Strata/Models/packs/q2_0/tokenizer",
 "model_name": "qwen3.8-flash-next-q2_0",
 "log": "/data/strata/q2_0-a.engine.log",
 "port": 5080,
 "gpu": 0,
 "mtp": true,
 "host": "127.0.0.1"
}
```

配置 B（`q2_0-b.json`）：与 A 完全相同，**只有两处不同**：

```diff
-  "log": "/data/strata/q2_0-a.engine.log",
-  "port": 5080,
+  "log": "/data/strata/q2_0-b.engine.log",
+  "port": 5081,
```

生成命令：

```bash
sed -e 's/"port": 5080/"port": 5081/' \
    -e 's|q2_0-a.engine.log|q2_0-b.engine.log|' \
    /data/strata/q2_0-a.json > /data/strata/q2_0-b.json
```

> **参数说明**：
> - `--resident-budget-gib 14`：每个实例最多用 14 GB 内存做专家池（两个共 28 GB，62 GiB 够）
> - `--expert-cache 8192`：直接给定，避免引擎自动分配过大
> - `--max-context 32768`：降到 32K 省 KV 显存（验证用，生产可按需调大）
> - `--vram-reserve-mib 1000`：每个实例给系统留 1 GB

### 3.3 启动两个实例

```bash
export STRATA_DATA_DIR=/data/strata

# GPU 权限需要 render 组，用 sg 包裹
sg render -c "cd /data/strata/terminal/0.1.56 && \
  STRATA_DATA_DIR=/data/strata \
  nohup ./python/bin/python3 -X utf8 -m serve.server \
    --engine strata --config /data/strata/q2_0-a.json \
    --host 127.0.0.1 --port 5080 --parallel 4 \
    > /data/strata/serve-a.out 2>&1 &"

sleep 2

sg render -c "cd /data/strata/terminal/0.1.56 && \
  STRATA_DATA_DIR=/data/strata \
  nohup ./python/bin/python3 -X utf8 -m serve.server \
    --engine strata --config /data/strata/q2_0-b.json \
    --host 127.0.0.1 --port 5081 --parallel 4 \
    > /data/strata/serve-b.out 2>&1 &"
```

> **踩坑**：不加 `sg render` 会报 `hipErrorNoDevice`（GPU 设备权限不足）。

### 3.4 验证

```bash
# 判据 1：两个进程
ps aux | grep serve.server | grep -v grep

# 判据 2：两个端口
ss -ltn | grep -E "5080|5081"
curl -sS http://127.0.0.1:5080/health
curl -sS http://127.0.0.1:5081/health

# 判据 3：各自推理
for p in 5080 5081; do
  curl -sS --max-time 90 -X POST "http://127.0.0.1:$p/v1/chat/completions" \
    -H "Content-Type: application/json" \
    -d '{"model":"qwen3.8-flash-next-q2_0",
         "messages":[{"role":"user","content":"高血压的诊断标准是什么？一句话回答"}],
         "max_tokens":80}'
done

# 判据 4：并发
curl ... :5080 ... -o /tmp/par-a.json &
curl ... :5081 ... -o /tmp/par-b.json &
wait
```

## 四、验证结果

### 4.1 启动耗时与资源

| 时刻 | 显存 | 内存 used | 状态 |
|---|---|---|---|
| 启动前 | 0.4 GiB | 7 GB | — |
| +45 s（加载中） | 31.6 GiB | 41 GB | A: 6776 experts / 8.72 GiB；B: 8192 experts / 10.55 GiB |
| +105 s（就绪） | 31.8 GiB | 44 GB | 两个都 ready |
| 停止后 | 0.3 GiB | 7 GB | 完全释放 |

**两个实例各约 80–96 秒就绪。**

### 4.2 判据 1：进程

```
226000  python3.12 -m serve.server --config q2_0-a.json --port 5080
226015  python3.12 -m serve.server --config q2_0-b.json --port 5081
```

### 4.3 判据 2：健康检查

```json
// :5080
{"status":"ok","max_context":32768,"model":"qwen3.8-flash-next-q2_0","loaded":true}
```

### 4.4 判据 3：各自推理

| 端口 | 耗时 | completion_tokens | 说明 |
|---|---|---|---|
| 5080 | 19.2 s | 80 | 冷启动，含 prefill |
| 5081 | 3.5 s | 80 | 热态 |

> 内容被 `max_tokens=80` 截断（全部消耗在思考链上），但**请求成功、返回了结构化响应**，足以证明推理链路通。

### 4.5 判据 4：并发

```
并发总耗时: 6.34 秒
  :5080 completion=40
  :5081 completion=40
```

两个请求同时发出、同时完成，**互不阻塞**。

## 五、关键发现：引擎会动态压缩 expert cache

启动时两个引擎各自想要的 cache：

| 实例 | 申请 | 实际 |
|---|---|---|
| A | 8.72 GiB | 被压缩 |
| B | 10.55 GiB | 被压缩 |
| 合计 | 19.27 GiB + KV + 开销 | **超过 31.9 GiB** |

**但两个都成功启动了**，最终显存 31.9/31.9 跑满。

说明引擎在显存不足时会**自动缩小 expert cache**（从 16384 slots 动态下调），而不是直接 OOM。

**推论**：
- 同一张卡跑两个实例是"能跑但互相挤压"（每个只有一半 cache）
- **双卡场景每卡独占 32 GB，不需要压缩，性能会好得多**

## 六、对硬件采购的意义

### 已排除的风险

| 风险 | 状态 | 依据 |
|---|---|---|
| 多实例进程/端口冲突 | ✅ 排除 | 两个进程、两个端口独立工作 |
| 两个实例共享模型文件冲突 | ✅ 排除 | 都用 `--ple-io mmap` 读同一份文件，无冲突 |
| 内存能否共存 | ✅ 排除 | 62 GiB 跑两个 14 GB arena，无 OOM、无 swap 抖动 |

### 仍未验证

| 风险 | 为什么没验 | 什么时候能验 |
|---|---|---|
| **两引擎（cuda + hip）共存** | 当前机器没有 NVIDIA 卡 | 5070 插上后 |
| **主板是否真 x8/x8** | 纯硬件规格 | 买前查规格书 |
| **机箱 5 槽空间** | 纯物理 | 买前量 |

### 结论

**软件机制这条最大的不确定性已消除。** 剩下三项都是买前就能确认的硬件事项。

## 七、对“NVIDIA + AMD 双卡”的直接支撑

这次验证证明的机制，正好是双卡方案需要的：

| 双卡方案需要 | 本次验证 |
|---|---|
| 两个独立服务进程 | ✅ |
| 各自独立的配置/端口/日志 | ✅ |
| 并发处理不同请求 | ✅ |
| 共享模型文件不冲突 | ✅ |

**双卡时唯一不同的是**：两个实例各用一张卡（`"gpu": 0` / `"gpu": 1`），而不是挤在一张卡上。

而且 Strata 的引擎还支持按实例指定后端（`engine_component.py:1118`）：

```python
backend = (cfg or {}).get("backend")
```

所以配置里写 `"backend": "cuda"`（5070）和 `"backend": "hip"`（R9700），两个实例各取所需。
