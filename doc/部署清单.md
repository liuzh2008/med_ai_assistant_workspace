# 部署清单

> **用途**：记录每一次"需要部署"的代码/脚本更新。**新的记录写在文件最上方**（倒序，最新在上）。
> **每条必填四项**：
> 1. **日期**（`YYYY-MM-DD`）；
> 2. **涉及的端与服务**——只写**服务器名称**，不写 IP/端口/路径：
>    - MedAI：`前端` / `主服务器` / `执行服务器`
>    - AiMed：`前端` / `后端`
>    - 不涉及的写「—」，不要省略该行；
> 3. **相关 SQL 脚本的链接**（相对本文件路径；无 SQL 写「—」）；
> 4. **需要更新的配置文件**（文件名 + 要新增/修改的配置项；纯代码改动写「—」）。
>
> **维护规则**：完成一个可部署的改动单元后**立即**追加；部署完成后在该条末尾追加 `已部署(YYYY-MM-DD)`。
> **配置文件注意**：`application.properties` 等配置**不随构建产物自动更新**，部署时必须同步改目标服务器上的同名文件；漏改会退回默认值或功能不可用。
> **服务器名称对照**：MedAI 主服务器 = 后端服务（8081）；MedAI 执行服务器 = 生成/执行节点（8082）；AiMed 前端 8085 / 后端 8083。
