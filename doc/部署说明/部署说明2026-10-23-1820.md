### 2.3 按需（幂等）：`DIAGNOSIS_ITEM_STATE`（表 + 序列 + 唯一索引）

```sql
SET DEFINE OFF
SET SERVEROUTPUT ON
DECLARE
  v_exists NUMBER;
BEGIN
  SELECT COUNT(*) INTO v_exists FROM user_tables WHERE table_name = 'DIAGNOSIS_ITEM_STATE';
  IF v_exists = 0 THEN
    EXECUTE IMMEDIATE 'CREATE TABLE DIAGNOSIS_ITEM_STATE (
      ID            NUMBER         NOT NULL,
      PATIENT_ID    VARCHAR2(64)   NOT NULL,
      ITEM_NAME     VARCHAR2(500)  NOT NULL,
      ITEM_TYPE     VARCHAR2(20)   NOT NULL,
      STATE         VARCHAR2(20)   NOT NULL,
      REASON        VARCHAR2(1000),
      OPERATOR_ID   VARCHAR2(64),
      CREATED_AT    TIMESTAMP      DEFAULT SYSTIMESTAMP,
      UPDATED_AT    TIMESTAMP      DEFAULT SYSTIMESTAMP,
      CONSTRAINT PK_DIAGNOSIS_ITEM_STATE PRIMARY KEY (ID)
    )';
    DBMS_OUTPUT.PUT_LINE('DIAGNOSIS_ITEM_STATE: table created');
  ELSE
    DBMS_OUTPUT.PUT_LINE('DIAGNOSIS_ITEM_STATE: table already exists, skipped');
  END IF;

  SELECT COUNT(*) INTO v_exists FROM user_sequences WHERE sequence_name = 'SEQ_DIAGNOSIS_ITEM_STATE';
  IF v_exists = 0 THEN
    EXECUTE IMMEDIATE 'CREATE SEQUENCE SEQ_DIAGNOSIS_ITEM_STATE START WITH 1 INCREMENT BY 1 NOCACHE';
    DBMS_OUTPUT.PUT_LINE('SEQ_DIAGNOSIS_ITEM_STATE: sequence created');
  ELSE
    DBMS_OUTPUT.PUT_LINE('SEQ_DIAGNOSIS_ITEM_STATE: sequence already exists, skipped');
  END IF;

  SELECT COUNT(*) INTO v_exists FROM user_indexes WHERE index_name = 'UK_DIAG_ITEM_STATE';
  IF v_exists = 0 THEN
    EXECUTE IMMEDIATE 'CREATE UNIQUE INDEX UK_DIAG_ITEM_STATE ON DIAGNOSIS_ITEM_STATE (PATIENT_ID, ITEM_NAME, ITEM_TYPE)';
    DBMS_OUTPUT.PUT_LINE('UK_DIAG_ITEM_STATE: unique index created');
  ELSE
    DBMS_OUTPUT.PUT_LINE('UK_DIAG_ITEM_STATE: unique index already exists, skipped');
  END IF;
END;
/
```

> 该表**仅**记录 AI 辅助界面「疑诊/补充诊断」的医生处置状态（PENDING/EXCLUDED/ADOPTED/IGNORED），不写入 `DIAGNOSIS`、不进 DRG/病案首页/质控/MCP 数据流。

## 6. 回滚预案

| 层 | 触发条件 | 命令 | 影响 |

| **后端（执行）** | 8082 不通、轮询停 | 同上，`docker tag med-ai-execution:bak-<日期> med-ai-execution:latest` → `docker compose -p execution-prod -f docker-compose-execution-image.yml --env-file .env.execution up -d --force-recreate` | 回到 0.9.298 |
| **数据库** | 仅当 §2.3 建表后确需撤销 | `DROP TABLE DIAGNOSIS_ITEM_STATE PURGE; DROP SEQUENCE SEQ_DIAGNOSIS_ITEM_STATE;` | 丢失医生已做的疑诊处置状态；已发生的审查结果不受影响 |

docker tag med-ai-main:latest        med-ai-main:bak-$(date +%Y%m%d-%H%M) 2>/dev/null || true

建议顺序：**先前端后后端**（前端回退快、无停机感），数据库最后考虑。

## 7. 风险与注意事项

| 风险 | 说明 | 规避 |
|---|---|---|
| 覆盖 `.env` | 生产 Oracle/密钥/加密盐都在里面，覆盖即不可用 | 拷贝清单只含镜像/脚本/config；动手前 `cp .env.main .env.main.bak-<日期>` |
| config 覆盖掉医院特有项 | `config/application.properties` 含 `hospital.default.id=cdwyy`、科室床号、HIS 模板路径；整包覆盖会抹掉现场改动 | 部署前 `diff` 备份；**只合并 voice 三行**，其余以现场为准 |
| 部署脚本自动补配置 | `deploy.sh` 会把镜像内默认配置中"现场缺失的 key"追加到外部 config | 部署后 `diff config/application.properties*` 检查新增项，异常项手工删除并重启 |
| 19:00 质控调度 | prod profile 下 `EmrQcScheduler` 每日 19:00 批量生成 EMR 质控评估 | 避开 19:00 前后 30 分钟 |
| 语音不可达 | 若 §1.4 的 DashScope 探测为 000，语音功能不可用 | 部署前确认网络策略；不可达时先上其余功能 |
| ASR key 变更 | 本次把五医院独立 key 统一为 `sk-ws-H.YMIYIYE…`；若需要按医院追踪百炼用量，需另行评估 | 与费用负责人确认后再上线 |
| `deploy.sh` 硬编码 1657/123 | 五医院该账号密码可能不同，6/8 自检会失败 | 见 §3.3 说明，改用页面核对 |
| 前端脚本删 nginx-proxy | `deploy-linux.sh` 会 `docker rm -f med-ai-nginx-proxy` | 先确认该容器归属，必要时注释该行 |
| 生产已是 0.9.299 | 若现场 `version.txt` 已是 0.9.299，说明有人先部署过 | 停手核对镜像构建时间与提交，必要时 bump 0.9.300 后重走流程 |
