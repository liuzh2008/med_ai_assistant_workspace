## 6. 回滚预案

| 层 | 触发条件 | 命令 | 影响 |
|---|---|---|---|
| **前端** | 页面白屏/首屏 500 | 用部署目录下上一版 `dist` 或旧镜像重新 `docker load` + `compose up -d --no-build` | 界面回到旧版，接口不受影响 |
| **后端** | `/api/health` 不通、接口 500 | `docker images | grep medteach-backend` 找 `backup-<时间戳>` 标签 → `docker tag … medteach-backend:latest` → `docker compose -f docker-compose-medteach-image.yml --env-file .env up -d` | 教学接口回到旧版；进行中的考核场次不受影响（数据在库） |
| **数据库** | 仅当本次建了表且要撤销 | `DROP TABLE CLINICAL_BATCH_ASSIGNMENT PURGE; DROP SEQUENCE SEQ_CLINICAL_BATCH_ASSIGNMENT;` | **会丢派题记录**；已开考不建议执行 |

建议顺序：**先前端后后端**（前端回退快、无停机感；后端回退要 60~90s）。数据库最后考虑。

## 7. 风险与注意事项

| 风险 | 说明 | 规避 |
|---|---|---|
| 覆盖 `.env` | 生产 Oracle/密钥都在里面，覆盖即服务不可用 | 拷贝清单明确只拷 5 个文件；动手前 `cp .env .env.bak-<日期>` |
| 停机窗口 | 后端重启 60~90s，期间学员无法进入 | 安排在非考核时段；提前通知 |
| 名单漏人 | 漏掉的工号开考后看不到场次 | 补名单后再点一次「执行」（同场次覆盖名单） |
| 一次三档不能配派题 | 三档会建 3 个场次 | 用「分发（单场次）」 |
| 训练档派题无效 | 训练档学员按资产自行进入 | 派题只在「一般考核/严格考试」生效 |
| 勾选变了再执行 | 会**新建**一个场次（旧的还在） | 结果区 30 分钟内可「撤销」 |
| 版本号与产物不一致 | 旧包被误拷入 | §1.1/§3.0/§4.0 三次核对 `LastWriteTime` + `version.txt` |

## 附录 B · 常见报错对照

| 现象 | 原因 | 处置 |
|---|---|---|
| 后端容器停在 `health: starting` | 缺表/缺列（`ORA-00942`/`ORA-00904`）或配置项缺失 | 查 `docker logs` → 补 §2 脚本；`UnsatisfiedDependencyException` 查 `.env` |
| 登录 403 | 主系统 CORS 不含 `http://10.120.11.43:8085`，或 nginx 未剥离 Origin | 确认前端 `nginx.conf` 有 `proxy_set_header Origin "";` |
| 科室列一直「查不到科室」 | 前端 nginx 缺 `/api/users/*/departments` 转发，或该工号在主系统无科室 | 核对 `nginx.conf:41` 的 location；换真实工号验证 |
| 执行报 409「所选资产中有 N 份不可用于考核」 | 资产被判不可考 | 在派题表里指定它（派题即纳入）或点「本次纳入」 |
| 执行报 400「一次三档会创建 3 个场次，不能同时指定派题」 | 编排语义选了三档 | 改「分发（单场次）」 |
| 学员看不到场次 | 未开考 / 工号不在名单 / 开了别的场次 | 核对状态、名单、场次号 |
| 前端页面还是旧版 | 浏览器缓存 或 包没换成功 | 强刷；核对 `version.txt` 与镜像 `Created` |
