# 2026-08-05

## fix(轮询): 修复生产环境"执行结果数据不能为空"无限报错（Prompt 102048~102051 卡死）

### 修改类型
缺陷修复（fix）

### 问题现象
生产环境（医院 cdwyy）主服务器 PromptPollingService 每 15 秒轮询时，对 Prompt 102048~102051 持续报错 `IllegalArgumentException: 执行结果数据不能为空`。仅这 4 条记录异常，其它记录正常。根因是 ENCRYPTED_DATA_TEMP 记录状态为 ENCRYPTED 但 EXECUTION_RESULT 为 NULL，且异常被 `processSubmittedPrompt` 的 catch 吞掉，导致无限重试刷屏、永不自愈。

### 根因（三层缺陷链）
1. **ClobManager 随机释放活跃 CLOB**（根因）：`activeClobs` 强引用 Map 永不释放（safeRelease/forceCleanup 无调用点），memoryUsage 只增不减；超 100MB 后 `cleanupOldClobs()` 无序迭代随机 free 一半活跃 Clob，可能释放其他线程刚创建、尚未绑定 JPQL 的 Clob，导致 Oracle CLOB 写入失败（EXECUTION_RESULT 落库为空）。只有恰在 free 窗口期的记录中招，故仅个别记录异常。
2. **completeProcessing 验证缺口**：第七步验证只检查状态和 ENCRYPTED_DATA，不验证 EXECUTION_RESULT 真实写入；CLOB 写入失败但行更新成功，状态照常推进到 ENCRYPTED，形成脏数据。
3. **主服务器无限循环**：processEncryptedData 遇 null 抛异常，被 catch 吞掉后 Prompt 保持"已提交"，每轮重复报错；超时清理机制对 ENCRYPTED 状态不重置，永不自愈。

### 修复内容
- `util/ClobManager.java`：`activeClobs` 改弱引用（WeakReference）持有，不再阻止 GC；`cleanupOldClobs`/`forceCleanup` 只移除已失效弱引用条目并校正内存统计，**绝不主动 free 存活 Clob**，消除随机释放竞态；`safeRelease` 适配弱引用。
- `service/EncryptedDataTempService.java`：`completeProcessing` 第七步验证新增 EXECUTION_RESULT 非空且长度 > 0 检查，CLOB 写入失败即抛异常回滚，状态保持 PROCESSING，从源头杜绝 ENCRYPTED+NULL 脏数据。
- `controller/ExecutionServerController.java`：两处（JPQL 写库路径 + 轮询模式）completeProcessing 失败 catch 中调用 `markAsError` 标记 ERROR（PROCESSING → ERROR 合法转换），避免记录永久卡在 PROCESSING；主服务器轮询 ERROR 分支将 Prompt 标记"执行失败"。
- `service/PromptPollingService.java`：`processEncryptedData` 遇 EXECUTION_RESULT 为 null 或内容为空时，不再抛异常无限重试，改为标记数据 ERROR + Prompt"执行失败"（新增 `markDataAsErrorAndFailPrompt`），存量脏数据部署后首轮轮询自动处理。

### 部署说明

- 再部署执行服务器（修复 1+2+3）→ 治本
- 如需恢复业务：将对应 Prompt 状态改回"待处理"可重新执行
