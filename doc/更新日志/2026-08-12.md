# 2026-08-12 更新日志

## 2026-08-12

### 修改类型
fix(病种匹配) — 生产环境病种匹配无内容显示

### 影响范围
- 后端 `QcDiseaseConfirmationService.java` — 新增公共自动确认方法 `autoConfirmFromMarkdown` / `hasConfirmedDiseases`（含"不匹配"块过滤）
- 后端 `CallbackController.java` — 自动确认改调公共方法，删除重复的 Markdown 解析代码
- 后端 `PromptPollingService.java` — 轮询路径保存结果后触发病种自动确认（3 处调用点）
- 后端 `QcDiseaseMatchController.java` — `getLatestMatchResult` 存量数据补偿确认
- 前端 `qcDiseaseMatchParser.js` — 过滤"不匹配"块

### 简要描述

**现象**：生产环境（cdwyy，轮询模式）病种匹配区域无内容显示，数据库 PROMPT_RESULT 中已有 LLM 输出的完整匹配结果（3 条匹配 + 13 条不匹配），但页面"已匹配病种"为空。

**根因**：
1. 病种匹配自动确认逻辑仅挂载在回调路径（`CallbackController`），而所有环境 `callback.enabled=false`，生产实际走轮询路径（`PromptPollingService`）。轮询路径保存 PromptResult 后只发布 Gate 2 事件，从不执行病种自动确认 → `QC_CONFIRMED_DISEASE` 永远为空 → 前端日常模式只展示已确认病种 → 无内容显示。
2. 次要缺陷：前后端解析器均不过滤 LLM 输出的"不匹配"块（触发诊断含"不匹配"），即使自动确认生效也会把不匹配病种错误确认为匹配项。

**代码修复**：
1. `QcDiseaseConfirmationService` 新增公共方法 `autoConfirmFromMarkdown(patientId, markdownResult)`：解析 Markdown（复用原 CallbackController 逻辑，新增"不匹配"过滤）→ 构建确认请求 → 自动确认；`hasConfirmedDiseases(patientId)` 幂等判断。
2. `CallbackController` 病种自动确认改调公共方法，删除重复解析代码。
3. `PromptPollingService` 在 `createPromptResultAndUpdateStatus` / `updatePromptStatusWithResult` / SENT 数据恢复路径 3 处保存结果后，按模板名判断触发 `publishDiseaseMatchAutoConfirm`（事务提交后执行，参照 Gate 2 事件模式）。
4. `QcDiseaseMatchController.getLatestMatchResult` 返回前检查：无已确认病种时对存量结果补偿自动确认（幂等，仅执行一次）。
5. 前端 `qcDiseaseMatchParser.js` 过滤"不匹配"块，与后端解析逻辑保持一致。

**验证**：
- 后端 `mvn compile` BUILD SUCCESS
- 前端解析器回归测试：生产环境 LLM 输出 16 个块 → 过滤后仅剩 3 条（AF / HT / COPD），无"不匹配"块
