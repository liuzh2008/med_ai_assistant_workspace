# 2026-08-08 更新日志

## 2026-08-08 09:10

### 修改类型
fix(LLM代理)

### 影响范围
- 后端 `LlmProxyController.java` — 代理转发错误恢复
- 后端 `LLMStreamProcessor.java` — 错误帧检测

### 简要描述

**根因**：DeepSeek API 账户余额不足（HTTP 402 Payment Required），执行服务器 `LlmProxyController` 透传到 DeepSeek API 时收到 402 错误。由于 `LlmProxyController` 只有 `.doOnError()` 记日志、没有 `.onErrorResume()` 错误恢复，`RuntimeException` 穿透到 `DispatcherServlet` 被转为 500 Internal Server Error，主服务器 `AIResponseService` 记录为 ERROR。

**排查链路**：
1. 本地 dev 模式主服务器日志显示 `status=500, path=/api/llm-proxy/chat/completions`（Spring Boot 默认错误格式）
2. SSH 到测试服务器检查 Docker 执行服务器 `med-ai-execution-server` 日志
3. 在 `08:52:50` 时刻发现关键日志：`status=402, body={"error":{"message":"Insufficient Balance",...}}`
4. 确认 DeepSeek API 余额耗尽是直接原因

**代码修复**：
1. `LlmProxyController.proxyChatCompletions()`：Flux 链添加 `.onErrorResume()`，上游 API 错误（402/401/5xx 等）不再穿透为 500，而是以 JSON 错误帧 `{"error":"LLM upstream error: ..."}` 返回
2. `LLMStreamProcessor.extractDelta()`：新增 `error` 字段检测，代理返回的错误帧不再被静默吞掉，而是通过 `wrapContent()` 传递给调用方

**紧急操作**：充值 DeepSeek API 账户余额

## 2026-08-08 09:45

### 修改类型
fix(LLM代理) — 上游API错误→临床友好中文消息

### 影响范围
- 后端 `LlmProxyController.java` — 上游HTTP状态码→中文友好错误帧
- 后端 `LLMStreamProcessor.java` — error帧→Flux.error()传播（替代之前的wrapContent静默处理）
- 后端 `AIResponseService.java` — 技术异常→中文友好错误响应

### 简要描述

在第一步修复的基础上，将技术性错误消息（如 `"AI service error: LLM API 调用失败: status=402, body={...}"` ）全链路转换为临床医生可理解、可直接转述给信息科的中文消息。

**三层转换链路**：
1. `LlmProxyController.mapUpstreamErrorToFriendlyMessage()` — 执行服务器解析上游HTTP状态码，映射为中文（如 402→余额不足、401→认证失败、429→请求频繁、503→不可用）
2. `LLMStreamProcessor.extractUpstreamError()` — 主服务器检测到error帧时以 `Flux.error()` 传播（替代之前 `extractDelta` 中wrapContent的静默吞掉方式），确保 `AIResponseService` 能捕获
3. `AIResponseService.mapToFriendlyError()` — 同时处理代理模式（已映射的中文直接传递）和直连模式（解析status=XXX格式再映射）

**前端展示效果**（前端 `ai.js` 已有 `json.error` 检测和展示逻辑）：
- 余额不足：`"AI服务出现错误: AI服务余额不足（错误码402），请联系信息科充值API账户"`
- 认证失败：`"AI服务出现错误: AI服务认证失败（错误码401），请联系信息科检查API密钥"`
- 服务不可用：`"AI服务出现错误: AI服务暂时不可用（错误码503），请稍后重试"`
