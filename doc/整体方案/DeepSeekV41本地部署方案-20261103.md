# DeepSeek V4.1 Flash 本地部署方案

**日期**：2026-11-03
**目标**：在现有硬件（1×R9700 32 GB + 62 GiB RAM）上部署 DeepSeek V4.1 Flash，作为"高价值分析"模型与现有 Qwen 分工
**结论**：**现有硬件可以跑，约 22–24 tok/s**。不需要买卡，只需下载 249 GB 模型文件。

---

## 一、结论摘要

| 项 | 值 |
|---|---|
| 模型 | DeepSeek V4.1 Flash，**ISTA-DASLab GSQ-RCO IQ2_XXS**（2.00 bpw） |
| 模型大小 | **138.2 GB**（4 个 shard） |
| Engram 表 | **110.6 GB**（从 SSD 流式读，不进内存） |
| **磁盘合计** | **248.8 GB** |
| 当前硬件 | 1×R9700 32 GB + 62 GiB RAM + 1.9 TB NVMe |
| **预期速度** | **22–24 tok/s**（按 62 GB RAM 插值官方实测） |
| 与 Qwen 对比 | Qwen 161 tok/s，**慢约 7 倍**，但质量是 DeepSeek V4.1 级别 |
| 是否需要买卡 | **不需要** |

---

## 二、为什么 Strata 能用 2-bit 跑 671B 级模型

DeepSeek V4.1 Flash 有两个分发版本，Strata 用的是小的那个：

| 版本 | 大小 | 说明 |
|---|---|---|
| unsloth UD-Q8_K_XL | **508.4 GB** | 9 shards，MXFP4 专家 288.8 GB |
| **ISTA-DASLab GSQ-RCO** | **138.2 GB（IQ2_XXS）** | 4 shards，2.00 bpw，**Strata 默认** |

ISTA 版三档：

| 量化 | bpw | 4 shards 合计 | 说明 |
|---|---|---|---|
| **IQ1_M** | 1.75 | **120.7 GB** | 最省，质量略降 |
| **IQ2_XXS** ⭐ | 2.00 | **138.2 GB** | **官方推荐默认** |
| **IQ2_XS** | 2.25 | **155.2 GB** | 质量最好 |

**Engram（n-gram 表）110.6 GB 是三种量化共用的一份**，从 SSD 按需读，不占内存。

## 四、现有硬件的实际预期

### 内存换算

```
物理 62 GiB
− 系统与页缓存 ≈ 10 GiB
= 模型可用 ≈ 52 GiB
```

对照官方表格（32 GB → 18.5，40 GB → 20.9）：

**插值：62 GiB 物理 → 约 52 GiB 可用 → 22–24 tok/s**

### speed 换算成业务指标

| 任务 | token | 22 tok/s | 对比 Qwen（161） |
|---|---|---|---|
| 诊断分析 | 14,130 | **10.7 分钟** | 1.5 分钟 |
| 首次病程 | 6,341 | 4.8 分钟 | 0.7 分钟 |
| 3,000 token prompt 预填 | 3,000 | 约 18 秒（按 167 tok/s prompt） | — |

> **93,000 token 的长 prompt，官方实测读取 78 秒。**

### 磁盘空间

| 项 | 大小 |
|---|---|
| IQ2_XXS 4 shards | 138.2 GB |
| Engram | 110.6 GB |
| **合计** | **248.8 GB** |

现有磁盘：`/data` 401 GB（可用约 350 GB）、`/mnt/win-data` 1.5 TB（只读）。

**建议放 `/mnt/win-data/Strata/Models/`**（和现有 Qwen 模型同目录），那里空间充足。

## 五、三个配置方案

### 方案 A：现有硬件直接跑（0 元）

| 项 | 值 |
|---|---|
| 硬件 | 1×R9700 + 62 GiB |
| 速度 | 22–24 tok/s |
| 磁盘 | 249 GB（`/mnt/win-data`） |
| 成本 | **0 元**（只需下载） |
| 限制 | **不能与 Qwen 同时跑**（内存不够） |

**使用方式**：需要时停 Qwen、起 V4.1；用完切回。

**适用场景**：疑难病例分析、会诊建议、教学案例——**不需要实时、但要求高质量**。

### 方案 B：加内存到 128 GB（+6,000 元）

| 项 | 值 |
|---|---|
| 硬件 | 1×R9700 + 128 GB |
| 速度 | **25.6 tok/s**（达到单卡上限） |
| 成本 | 6,000（2×32 GB） |
| 好处 | **V4.1 与 Qwen 可以共存**（Qwen 30 GB + V4.1 90 GB） |

**这是性价比最高的一步**——6,000 元买到"两个模型同时在线"。

### 方案 C：加 3 张 R9700（+48,300 元起）

| 项 | 值 |
|---|---|
| 硬件 | 4×R9700 + 251 GB RAM |
| 速度 | **59 tok/s**（全部专家进显存） |
| 成本 | 卡 48,300 + 主板/内存/电源约 30,000 = **约 7.8 万** |
| 好处 | 速度 2.5 倍，且能同时跑 Qwen |

**只有在 V4.1 成为主力时才值得。**

## 六、与 Qwen 的分工建议

| 任务 | 用哪个 | 理由 |
|---|---|---|
| 夜间批量文书（诊断分析/诊疗计划/小结） | **Qwen（161 tok/s）** | 量大、要求快、质量 3.56 分够用 |
| 疑难病例讨论材料 | **V4.1（23 tok/s）** | 量小、质量要求高 |
| 会诊意见整理 | **V4.1** | 同上 |
| 教学案例生成 | **V4.1** | 同上 |
| 实时入院记录/首次病程 | **Qwen** | 有时限（8h/24h），不能等 10 分钟 |

**关键**：V4.1 慢 7 倍，但只用于"每天几十份"的高价值场景，不影响主流程。

## 七、落地步骤

### 第 1 步：下载模型（249 GB）

```bash
# 4 个 shard + Engram，走 hf-mirror
export HF_ENDPOINT=https://hf-mirror.com
export HF_HUB_DISABLE_XET=1        # hf-mirror 不支持 Xet

# 仓库：ISTA-DASLab/DeepSeek-V4.1-Flash-1017-GSQ-RCO-GGUF
# 需要下载：
#   DeepSeek-V4.1-Flash-1017-GSQ-RCO-IQ2_XXS-0000{1..4}-of-00004.gguf   138.2 GB
#   DeepSeek-V4.1-Flash-Engram-IQ4_NL.gguf                              110.6 GB
#   还需要 Unsloth 的 5.8 MB metadata shard（pack_gguf --engram-meta 用）
```

> **注意**：下载量大（249 GB），按 10 MB/s 约 7 小时。建议夜间跑。

### 第 2 步：打包（`tools/dsv41/pack_gguf.py`）

```bash
cd /data/strata/terminal/0.1.56
./python/bin/python3 tools/dsv41/pack_gguf.py \
  --gguf-dir <模型目录> --out <pack 目录>
```

### 第 3 步：启动

```bash
# 停掉 Qwen
pkill -f "q2_0-.*\.json"

# 起 V4.1
sg render -c "cd /data/strata/terminal/0.1.56 && \
  STRATA_DATA_DIR=/data/strata \
  nohup ./python/bin/python3 -X utf8 -m serve.server \
    --engine strata --config /data/strata/dsv41.json \
    --host 127.0.0.1 --port 5082 --parallel 1 \
    > /data/strata/serve-dsv41.out 2>&1 &"
```

### 第 4 步：验证

```bash
curl -sS http://127.0.0.1:5082/health
curl -sS -X POST http://127.0.0.1:5082/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-v4.1-flash","messages":[{"role":"user","content":"什么是脓毒症？"}],"max_tokens":200}'
```

## 八、风险与注意事项

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| 1 | **下载 249 GB** | 7 小时+，可能中断 | 断点续传，分批下 |
| 2 | **与 Qwen 抢内存** | 同时跑会 OOM | 方案 A 只能二选一；方案 B 加内存 |
| 3 | **首 token 慢** | 长 prompt 预填 78 秒（93K token） | 用短 prompt，或接受 |
| 4 | **SSD 读 Engram** | 磁盘 IO 压力大 | 用 NVMe（现有 1.9 TB），不要机械盘 |
| 5 | **2-bit 质量** | IQ2_XXS 比 Q8 略降 | 官方推荐默认档，医院文书场景够用 |

---

## 九、我的建议

**先做方案 A（0 元）验证质量，再决定要不要花 6,000 加内存。**

理由：
1. 现有硬件能跑，不需要任何采购
2. 先看 V4.1 在真实病例上的表现（对比 Qwen 的 3.56 分）
3. 如果质量明显更好、且确实需要"同时在线"，再加内存到 128 GB

**不建议一步到位买 4 卡**——59 tok/s 的收益，只有在 V4.1 成为主力时才值 7.8 万。
