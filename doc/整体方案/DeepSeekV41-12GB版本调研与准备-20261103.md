# DeepSeek V4.1 Flash：12 GB 显卡版本调研与准备

**日期**：2026-11-03
**问题**：12 GB 显存能不能跑 DeepSeek V4.1 Flash？需要什么准备？
**结论**：**能跑。** Strata 0.2.4 起官方支持 12 GB 显卡，最低配置 12 GB 显存 + 46 GB 内存 + 239 GB SSD。现有 R9700（32 GB）属于该档位里最快的单卡。

---

## 一、结论摘要

| 项 | 结果 |
|---|---|
| 12 GB 显卡能否加载 | ✅ **能**，三个量化版都支持 |
| 最低配置 | 12 GB 显存 + **46 GB 内存** + **239 GB NVMe** |
| 机制 | 「热门专家缓存」：常用专家留内存，其余放 SSD 按需读 |
| 当前硬件（R9700 32 GB + 62 GiB） | ✅ 可跑，预计 **20–24 tok/s** |
| 提速手段 | **DSpark 推测解码**（四卡实测提速约 2 倍） |
| Strata 版本要求 | **0.2.4+**（当前 0.1.56，需升级） |

---

## 二、12 GB 卡能跑的证据

### 2.1 官方说明（Strata 0.2.4，2026-10-24）

来源：[小众软件报道](https://www.appinn.com/strata-0-2-4-deepseek-v4-1-flashterminal-0-2-4-1/)

> **只需要一张 RTX 3060 12GB 显卡，搭配 46GB 内存**，就能在本地运行 DeepSeek V4.1-Flash 的完整架构量化模型。甚至还能达到每秒 8～10 个 token 的生成速度。

官方最低配置：

| 项 | 要求 |
|---|---|
| 显卡 | **12 GB 起**（实测用 RTX 3060） |
| 内存 | **46 GB 实测可用**，推荐 64 GB |
| 硬盘 | **239 GB 起**，推荐 NVMe SSD |

### 2.2 为什么 12 GB 能跑 138 GB 的模型

DeepSeek V4.1 Flash 是 **MoE（混合专家）** 架构：40 层 × 384 专家，每次生成只调用 top-6。

Strata 的机制：

```
显存（12 GB）  → 密集权重 + 最热的少量专家
内存（46 GB）  → 次热的专家（常驻）
SSD（239 GB）  → 冷专家（按需读）
```

**所以显存大小只决定"热专家留多少"，不影响"能不能跑"。**

## 三、三个量化版本（含 Engram 的总下载量）

| 量化 | 精度 | 总下载 | 专家部分 | 质量（相对原版 PPL） |
|---|---|---|---|---|
| **IQ1_M** | 1.75-bit | **239 GB** | 120.7 GB | +21%（最小，明显弱） |
| **IQ2_XXS** ⭐ | 2.00-bit | **257 GB** | 138.2 GB | +15.5%（code +8.6%） |
| **IQ2_XS** | 2.25-bit | **274 GB** | 155.2 GB | +7.3%（code +3.2%，最接近原版） |

**Engram（n-gram 表）110.6 GB 是三档共用的一份**，从 SSD 流式读，不占内存。

> 据 ISTA-DASLab 测试，即使压缩最狠的 1.75-bit 版，在数学、知识问答、编程三项基准上平均仍达原版的 **98.7%**。

**建议**：磁盘够就选 **IQ2_XS（274 GB）**，质量损失最小；否则 **IQ2_XXS（257 GB）** 是官方默认。

## 四、实测速度（两个数据源，差异由内存导致）

### 4.1 官方 0.2.4 发布数据（IQ2_XXS）

| 硬件配置 | 生成速度 |
|---|---|
| RTX 3060 12 GB + 46 GB | **8–10 tok/s** |
| RTX 5070 12 GB + 64 GB | **约 5 tok/s** |
| 单张 R9700 | **约 11 tok/s** |
| 四张 R9700 | 约 31 tok/s |
| **四张 R9700 + DSpark** | **55–69 tok/s** |

> 反直觉：3060 比 5070 快——瓶颈在 CPU 和 SSD，不在显卡。

### 4.2 本地 `dsv41_fit.py` 内置实测（2026-11-01，IQ2_XXS）

| 配置 | decode |
|---|---|
| 1×R9700 + **251 GB RAM** | **25.6 tok/s** |
| 1×R9700 + 40 GB | 20.9 tok/s |
| 1×R9700 + 32 GB | 18.5 tok/s |
| 1×R9700 + 24 GB | 15.0 tok/s |
| 1×R9700 + 16 GB | 8.0 tok/s |
| 4×R9700 + 251 GB | 59.0 tok/s |

### 4.3 两个数据源的差异说明

| 来源 | 单 R9700 | 条件 |
|---|---|---|
| 官方 0.2.4 发布 | ~11 tok/s | 推测 64 GB RAM 级 |
| 本地 `dsv41_fit.py` | 25.6 tok/s | 251 GB RAM，无限制 |

**差异完全来自内存**——专家能留多少在 RAM 里，直接决定速度。

### 4.4 当前硬件的预期

```
物理 62 GiB − 系统/页缓存 ≈ 52 GiB 可用
对照官方：40 GB → 20.9，32 GB → 18.5
插值：62 GiB → 约 21–23 tok/s
```

## 五、DSpark：被忽略的提速手段

DSpark 是模型自带的**推测解码器**（`dspark-DeepSeek-V4.1-Flash-1017-Q8_0.gguf`）。

原理：小模型猜下一批 token，大模型一次验证多个。

实测效果（四卡）：

```
31 tok/s（无 DSpark） → 55–69 tok/s（有 DSpark）
```

**提速约 2 倍。**

单卡按比例推算：20–23 tok/s 可能提到 **35–45 tok/s**。

> ⚠️ 单卡 + DSpark 官方未给出实测数据，上述为外推，需实测确认。

## 七、准备步骤

### 第 1 步：升级 Strata 到 0.2.10

```bash
export STRATA_DATA_DIR=/data/strata
cd /data/strata/terminal/0.1.56

# 官方 feed 走 GitHub 会超时，用镜像
export STRATA_UPDATE_FEED="https://gh-proxy.com/https://github.com/Niko1221/Strata/releases/latest/download/strata-feed.json"
./bin/strata update --backend hip
```

> **风险**：升级后 `q2_0` 现有配置可能需要重调（引擎参数有变）。**建议先备份** `/data/strata/q2_0-linux.json` 和 `q2_0-a/b.json`。

### 第 2 步：下载模型（244–274 GB）

```bash
export HF_ENDPOINT=https://hf-mirror.com
export HF_HUB_DISABLE_XET=1     # hf-mirror 不支持 Xet

# 仓库：ISTA-DASLab/DeepSeek-V4.1-Flash-1017-GSQ-RCO-GGUF
# 需下载：
#   DeepSeek-V4.1-Flash-1017-GSQ-RCO-IQ2_XS-0000{1..4}-of-00004.gguf   155.2 GB
#   DeepSeek-V4.1-Flash-Engram-IQ4_NL.gguf                              110.6 GB
#   dspark-DeepSeek-V4.1-Flash-1017-Q8_0.gguf                           （DSpark 推测解码器）
#   以及 Unsloth 的 5.8 MB metadata shard（pack_gguf --engram-meta 用）
```

**存储位置**：

| 位置 | 可用 | 评价 |
|---|---|---|
| `/data` | 约 350 GB | 够，但装完只剩 100 GB |
| `/mnt/win-data` | 1.5 TB | 宽裕，但**当前只读挂载** |

**建议**：放 `/mnt/win-data`（需改成读写挂载），或清理 `/data`。

### 第 3 步：打包

```bash
cd /data/strata/terminal/0.1.56
./python/bin/python3 tools/dsv41/pack_gguf.py \
  --gguf-dir <模型目录> --out <pack 目录> --engram-meta <metadata shard>
```

### 第 4 步：配置并启动

```json
{
  "exe": "component:strata-engine",
  "backend": "hip",
  "args": [
    "--pack", "<pack 目录>",
    "--expert-cache", "auto",
    "--max-context", "65536",
    "--vram-reserve-mib", "1500",
    "--resident-budget-gib", "48",
    "--mtp", "<dspark 路径>"
  ],
  "port": 5082,
  "gpu": 0
}
```

> **注意**：V4.1 用**独立的 `strata-dsv41` 引擎**，不会替换 Qwen 的引擎（官方说明："DeepSeek 使用独立的 strata-dsv41 引擎，不会替换此前运行 Qwen 模型的引擎"）。

### 第 5 步：验证

```bash
curl -sS http://127.0.0.1:5082/health
curl -sS -X POST http://127.0.0.1:5082/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-v4.1-flash","messages":[{"role":"user","content":"什么是脓毒症？"}],"max_tokens":200}'
```

## 九、与现有 Qwen 方案的关系

| 项 | Qwen 3.8 Flash | DeepSeek V4.1 Flash |
|---|---|---|
| 显存占用 | 32 GB 显存的 59% | 32 GB 显存的 ~23% |
| 内存占用 | 30 GB arena | **48–52 GB** |
| 磁盘 | 62 GB | **244–274 GB** |
| 速度 | 161 tok/s | 20–24 tok/s（+DSpark 可能 35–45） |
| 质量 | 诊断分析 3.56/5 | 未测（DeepSeek 官方模型级别） |

**关键冲突**：两者都是 35 GB+ 级模型，**62 GiB 内存装不下两个**。

| 方案 | 可行性 |
|---|---|
| 同时跑 | ❌ 内存不够 |
| 二选一（切换） | ✅ 需停一个、起另一个（各 1–2 分钟） |
| 加内存到 128 GB | ✅ 可共存（Qwen 30 + V4.1 80 = 110 GB） |

## 十二、我的建议

**分两步走：**

**第一步（现在，0 成本）**：只升级 Strata 到 0.2.10，**不下载 V4.1**。
- 验证升级后 Qwen 仍正常（161 tok/s）
- 享受 Prefill +88%、DFlash2 等收益
- 如果 Qwen 坏了，还能回滚

**第二步（确认需求后）**：下载 V4.1 IQ2_XS（274 GB）+ DSpark。
- 用真实病例对比质量
- 决定是否长期保留

**不建议**一步到位下载——257 GB 下载一天，如果发现质量不如预期或内存不够，浪费很大。
