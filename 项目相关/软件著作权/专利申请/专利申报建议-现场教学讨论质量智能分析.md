## 二、技术背景与要解决的技术问题

### 2.1 背景技术现状

1. **会议转写与纪要产品高度成熟但无教学基线概念**：讯飞听见、飞书妙记、TicNote 等产品可完成录音转写与通用摘要，但摘要为"无基线"的内容浓缩，无法回答"该讨论是否达成了课前设定的教学目标"。
2. **智慧课堂分析专利侧重行为多模态**：现有课堂教学分析方案（如 CN109087222A 课堂数据分析方法及系统）基于人脸数据、学生行为数据、教师行为数据及语音数据做课堂行为统计，面向 K12 课堂纪律与行为分析，不涉及"预期教学内容覆盖度"的语义级测量。
3. **医学现场教学（教学查房、病例讨论）长期缺乏结构化质量记录**：讨论质量依赖教师课后凭印象回忆，无客观记录手段；学员在讨论中的表现亮点与知识盲区无法沉淀；讨论内容无法转化为可分发的知识点。

### 2.2 要解决的技术问题（按重要性排序）

1. 如何将课前设定的教学预期（讨论提纲）转化为可计算的参照基线，使 LLM 能对实际讨论内容做**覆盖度对照分析**，而非泛泛摘要；
2. 如何在录音设备与教学系统物理解耦（系统内零录音操作）的前提下，将课后异步获取的权威转写内容与对应教学会话**准确绑定**；
3. 如何将教师课中的轻量人工判断（三态标记）作为高价值稀疏信号注入 LLM 提炼过程，提升输出与教师现场判断的一致性；
4. 如何在医院内网（无外网权限）环境下安全接入第三方语音云服务与大模型服务；
5. 如何将发布的讨论分析结果自动转化为可推送至学员个人知识库的知识点，形成"计划→教学→测量→沉淀"闭环。

## 三、核心发明构思（一句话）

**课前由 LLM 依据绑定教案生成讨论提纲并经教师审核确认为"预期覆盖基线"，课中采集教师三态稀疏标记，课后将「提纲基线 + 异步精修转写全文 + 语音云厂商 AI 纪要 + 教师标记」四类异构数据源融合输入大语言模型，强制输出与提纲逐条对照的"讨论核心 / 薄弱环节 / 亮点"三要素结构化分析，经教师审核（可编辑后重新提炼、版本不覆盖）发布后，事件驱动知识点归集推送。**

发明构思的关键词：**预期基线对照**。本方案与一切"录音→转写→摘要"现有技术的本质区别在于——摘要对象不是孤立的讨论内容，而是"实际讨论"相对于"课前注册预期"的偏差测量。

## 五、权利要求布局建议

### 5.1 独立方法权利要求（主线）

一种现场教学讨论质量智能分析方法，其特征在于包括：

1. **课前基线注册**：获取与讨论会话强制绑定的教案数据（教学目标、重难点、病例信息），由大语言模型生成包含若干引导问题的讨论提纲，经教师审核确认后生效为预期覆盖基线，生效后提纲只读；
2. **课中数据采集**：教师通过独立录音硬件完成课堂录音（系统内零录音操作）；教师在教学界面提交带时间戳的三态标记（正确/存疑/需补充），标记前端暂存并在结束讲课时批量提交；
3. **课后多源融合提炼**：教师选定与时间窗筛选列表中的录音后，经代理链路拉取该录音的转写全文与厂商 AI 纪要；将「预期覆盖基线 + 转写全文 + 厂商 AI 纪要 + 教师标记」融合输入大语言模型，输出三要素结构化分析——讨论核心（含提纲覆盖对照）、薄弱环节（含遗漏引导问题识别）、亮点（含教师标记印证）；
4. **审核发布闭环**：三要素可编辑，支持将编辑后文本重新输入大语言模型精炼并生成新版本（不覆盖原始输出）；发布后将最终三要素入库并触发知识点归集事件。

### 5.2 独立系统权利要求

一种现场教学讨论质量智能分析系统，其特征在于包括：

- **提纲生成模块**：教案绑定校验（无教案禁止创建会话）、LLM 提纲生成、教师审核与只读控制；
- **会话状态管理模块**：DRAFT→IN_PROGRESS→PUBLISHED 状态流转，以结束时间戳空/非空区分课中与课后阶段；
- **录音绑定模块**：时间窗筛选录音列表、上传滞后提醒、周期刷新、教师确认绑定；
- **融合提炼模块**：转写全文与厂商纪要拉取、四源融合 Prompt 组装、LLM 三要素提炼、重新提炼版本管理；
- **发布联动模块**：三要素发布、知识点归集事件分发；
- **代理接入模块**：内网主服务器与外网代理执行服务器双节点架构，凭证隔离与审计。

### 5.3 从属权利要求（候选 8-10 条）

| # | 从属方向 | 要点 |
|---|---------|------|
| 1 | 双轨语音协同 | 实时轨（流式 ASR 大屏回显，中间结果/最终结果双态渲染）与精修轨（异步转写+厂商 AI 整理）物理解耦并行，精修轨为 LLM 提炼唯一权威语音输入 |
| 2 | 标记时间对齐 | 三态标记时间戳与转写 segments 时间戳对齐，定位讨论片段并引导 LLM 关注 |
| 3 | 标记暂存策略 | 标记前端暂存、结束讲课批量提交、页面卸载前提醒 |
| 4 | 时间窗绑定 | 最近 1 天 + 整理完成状态筛选；最新录音超阈值触发上传滞后提醒；周期轮询刷新 |
| 5 | 自动匹配 | 结束讲课后自动匹配最新录音完成绑定（v2 特征，先行写入扩大保护范围） |
| 6 | 覆盖对照输出 | 三要素输出强制逐条标注提纲引导问题的覆盖状态（充分讨论/讨论不充分/未讨论） |
| 7 | 重新提炼版本化 | 修改后重新提炼生成新版本，保留原始 LLM 输出供比较回溯 |
| 8 | 双节点代理 | 主服务器不持有第三方凭证，执行服务器 JWT + IP 白名单 + 审计日志代理全部外部调用 |
| 9 | 知识点归集联动 | 发布事件驱动知识点提取并推送学员个人知识库收件箱（引用式描述，不主张归集方法本身） |
| 10 | 说话人分离扩展 | 实时轨开启说话人分离并结合学员注册信息自动匹配发言人（v2 特征，先行写入） |

## 七、现有技术初步检索与 FTO 风险

### 7.1 初步检索结论（公开网络初检，2026-07-31）

| 领域 | 代表性现有技术 | 与本案差异 |
|------|--------------|-----------|
| 会议转写纪要 | 讯飞听见、飞书妙记、TicNote（出门问问） | 无基线通用摘要，无教学预期对照机制 |
| 课堂数据分析 | CN109087222A（人脸/行为/语音多模态行为统计） | 面向 K12 行为分析，无语义级内容覆盖测量，无 LLM 基线对照 |
| 智慧课堂 | 科大讯飞智慧课堂产品线 | 以授课内容采集与学情统计为主，未见"课前注册提纲基线→课后三要素对照"机制 |
| 医学教学 | 基础医学学科大模型（智慧高教平台） | 面向自主学习与考核评价，无现场讨论录音分析机制 |

**初步判断**：未发现与核心发明构思（预期提纲基线对照 + 四源融合三要素提炼）直接撞车的公开文献，具备新颖性基础。

### 7.2 FTO 风险与对策

| 风险 | 说明 | 对策 |
|------|------|------|
| 语音厂商专利密集 | 出门问问（TicNote）、科大讯飞在 ASR/转写领域专利众多 | 权利要求严格落在**应用编排层**（基线对照、融合提炼、绑定机制），不主张任何 ASR 算法本身；ASR 均以"调用第三方服务"表述 |

## 八、申报时机与策略建议

1. **先申报、后公开**：系统正在成都市第五人民医院验证，任何扩大验证、对外汇报、演示视频发布均可能构成使用公开。建议交底书定稿后**立即申报**，再进行大规模对外展示。
2. **v2 特征先行写入**：讯飞实时轨、录音自动匹配、说话人分离学员匹配虽为 v2 规划，专利保护的是技术方案而非已实施代码，应全部写入说明书与从属权利要求，避免 v2 实施时被自身公开破坏新颖性。
3. **一案申请，暂不拆案**：双轨协同（创新点 2）与三要素对照（创新点 1）服务于同一发明构思（现场教学讨论质量智能分析），符合单一性；若正式检索显示双轨方向有独立授权前景且预算允许，可考虑分案。
4. **申请人类型**：按《合作开发与商业转化方案》，本项目专利拟与软件公司、学院三方协商归属，申报前需先明确申请人/发明人署名方案。
5. **配套保护**：Prompt 模板（三要素提炼 Prompt）作为技术秘密另行保护，不在说明书中完整公开具体 Prompt 文本，仅描述其输入构成与输出约束。
