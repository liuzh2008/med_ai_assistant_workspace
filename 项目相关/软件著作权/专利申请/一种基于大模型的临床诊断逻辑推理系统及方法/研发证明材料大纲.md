## 第二章 国内外研究与技术现状

| 节号 | 标题 | 内容要点 |
|------|------|---------|
| 2.1 | 医疗AI辅助诊断领域发展现状 | 国外：LLM 医疗知识考试 84-90% 准确率 vs 真实临床 45-69%（Gong 2025 JMIR 系统综述）；国内：IMQC（AAAI 2025）、Dual RAG + Check 架构 |
| 2.2 | LLM 临床诊断推理技术现状 | 模式识别式（System 1）快速一次性输出——适用于典型病例，面对多系统共病/罕见病排查/治疗无效场景时遗漏率和幻觉率显著上升 |
| 2.3 | 现有技术的五大核心缺陷 | ① 单步推理精度随复杂度指数下降；② 输出格式（JSON）稳定性不足；③ 缺乏认知偏差对冲机制；④ LLM 调用不可靠（超时/截断）；⑤ 推理过程不可审计 |
| 2.4 | 国内同类系统对比 | 与 UpToDate、BMJ Best Practice、临床路径系统、CDSS 知识库系统对标——均为知识检索型，非推理生成型 |

## 第三章 项目调研与分析

| 节号 | 标题 | 内容要点 |
|------|------|---------|
| 3.1 | 临床需求调研 | 成都市第五人民医院心血管一病区 + 盐亭县人民医院的复杂/不典型病例诊断痛点：症状不特异、多系统共病、治疗无效需重新评估 |

| 3.3 | 调研结论与技术路线确定 | 确认"认知任务分解 + 分层-展开策略 + 断言化验证 + 断点续做"的八步推理架构为最优技术路线 |

## 第四章 项目需求

| 节号 | 标题 | 内容要点 |
|------|------|---------|

| 4.3 | 安全与合规需求 | ① 医生逐级审批关卡（4 个暂停点）；② AI 生成内容 source 标识；③ 推理过程全链路可追溯可审计 |

## 第五章 总体架构设计

| 节号 | 标题 | 内容要点 |
|------|------|---------|
| 5.1 | 三层系统架构 | 前端推理编排层（LogicalDiagnosisPanel.vue）+ 后端模板层（10 个 JSON 模板 + manifest.json）+ LLM 推理层（analyzeLLM 接口复用） |
| 5.2 | 前端驱动同步执行模式 | 区别于传统"后端提交-轮询"Pipeline：前端分解步骤→组装 Prompt→addPrompt→analyzeLLM→saveAIResult，零轮询，后端零新增 Controller |
| 5.3 | 设计原则 | ① 认知任务分解（每步聚焦 1 个认知任务）；② 认知负载控制（每步 ≤5-7 项）；③ 原子化持久化（任一步失败可单独重试）；④ 关注点分离（编排/模板/推理三层解耦） |

## 第七章 关键技术点

| 节号 | 标题 | 对应专利步骤 | 核心创新 |
|------|------|------------|---------|
| 7.1 | 认知任务分解——8 步流程拆分 | S1~S45 | 将复杂诊断推理拆解为每步不超过 5-7 项的独立认知子步骤，从架构层面解决 LLM 精度随复杂度指数下降问题 |
| 7.2 | 分层-展开策略 | S31~S32 | 先按 VINDICATE 病因机制归类（≤7 类），再逐类展开具体假设（每类≤5 个），总覆盖 15-35 个假设，同时保持 LLM 每步处理量不超限 |
| 7.3 | Prompt 模板工程 | S1~S45 | 10 个 JSON 模板：模板仅含指令和输出格式，禁止变量名；organizedData 自动前置；Markdown 全流程格式 |
| 7.4 | 前端驱动编排架构 | 系统层 | submitAndWait 编排函数 + Promise.all 并行获取 + 原子化 API 调用链 + 零轮询同步执行模式 |
| 7.5 | 输出断言化与人工验证 | S46 | parseAssertions 解析 Markdown `- [ ]` 断言清单 → 可勾选/编辑/新增交互面板 → handleSave 逐行删除+追加持久化 → 仅确认项进入下游 |
| 7.6 | 断点续做机制 | 系统层 | checkPreviousTask → loadCompletedSteps（三策略+可消费结果池精确匹配）→ resumeFromStep → waitForDoctorSave 逐级审批推进 |
| 7.7 | 假设级并行推理 | S41~S45 | Promise.all 假设间完全并行 + async/await 假设内串行链，端到端耗时从 N×Time 压缩为并行 Time |
| 7.8 | 逆向审视与认知偏差检查 | S44 | 魔鬼代言人强制反向质疑 + 四种认知偏差检查清单（可得性/锚定/确认/代表性），系统性对冲 LLM 固有偏差 |
