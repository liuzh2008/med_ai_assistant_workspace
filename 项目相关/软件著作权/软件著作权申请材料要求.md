# 计算机软件著作权登记申请材料详细要求

## 一、源代码文档要求

### 1. 提交规则

- 代码量 **≥ 3000行**：提交**连续前30页 + 后30页**（共60页）
- 代码量 **< 3000行**：需**全部提交**，仍需满足格式要求

### 2. 排版规范

| 项目 | 要求 |
|------|------|
| 纸张 | A4纸（297mm×210mm） |
| 每页行数 | **≥ 50行**（最后一页除外），空行和注释**不计入** |
| 字号 | 不大于13号（建议**小五号/10.5pt**） |
| 字体 | 等宽字体（推荐**宋体**） |
| 行距 | 固定值**12磅** |
| 页眉 | 左上角标注"**软件名称+版本号**"（须与申请表完全一致） |
| 页码 | 右上角阿拉伯数字连续标注（格式：**第X页 共60页**） |
| 装订 | 单面打印，左侧预留**1cm装订线** |

### 3. 前30页/后30页内容要求

- **前30页**：必须从程序**起始部分**开始（如 `main()` 方法、程序入口、登录模块起始代码）
- **后30页**：必须包含程序**结束标志**（如 `return` 语句、持久化代码、程序退出语句）
- 前后两部分**各自需连续**，但彼此之间允许不连续

### 4. 代码内容注意事项

- 需**删除所有空行**和无意义注释
- **保留**版权声明和作者信息
- 框架自动生成代码占比建议**不超过20%**
- **不限**编程语言
- **避免**提交以下内容：
  - 加密/压缩的不可读格式
  - 纯框架代码
  - 完全抄袭的开源代码

## 二、软件说明书（用户操作手册）要求

### 1. 类型选择

以下类型**任选一种**：
- 用户操作手册（**最常见**）
- 用户使用说明书
- 设计说明书
- 用户设计说明书

### 2. 页数要求

| 源代码行数 | 说明书最低页数 |
|-----------|--------------|
| ≤ 3000行 | **5页以上** |
| 3000 ~ 10000行 | **15页以上** |
| > 10000行 | **20页以上** |

### 3. 内容结构

- **软件概述**：功能介绍、开发背景
- **主要功能描述**：核心功能清单
- **运行环境说明**：操作系统、硬件要求、依赖环境
- **操作流程说明**：用户操作步骤
- **功能界面截图**：间隔2-3页至少出现一次截图，须清晰完整，配文字说明
- **常见问题解答**（可选）

### 4. 排版要求

- A4纸，每页 **≥ 30行**（有图除外）
- 页眉标注**软件名称和版本号**，须与申请表**完全一致**
- 需有**封面和目录**（不计入页数）
- **不能有**水印、大段空白
- 超过60页时提交**前30页和后30页**

### 5. 重要规则

- **功能描述须与源代码实现一一对应**
- 截图须为**软件实际运行界面**
- 图文并茂，每个截图配对应文字说明

---

## 三、申请表填写要点

### 1. 基本信息

- **软件全称**：包含"品牌+功能+软件"，如"XX医疗AI辅助诊疗系统V1.0"
- **版本号**：统一为 **V1.0** 格式；若版本号 ≥ 2.0 需提供上一版本软著证书
- **主要功能描述**：**500-1300字**，与源代码实现一一对应

### 2. 重要日期

- **开发完成日期**：软件固定在有形载体上的日期，须 **≤ 首次发表日期**
- **首次发表日期**：可与开发完成日期相同
- 开发完成日期应**早于**申请日期

### 3. 一致性要求（重点）

> ⚠️ **申请表、源代码页眉、说明书页眉中的软件名称和版本号必须完全一致！**

## 四、身份证明材料

### 个人申请

- 身份证**正反面**复印件
- 申请人**签字**（原件）

### 企业申请

- **营业执照副本**复印件
- 加盖公司**鲜章（红章）**
- **企业法人或授权代表**签名

---

## 五、鉴别材料规范

### 程序鉴别材料（源代码）

- **前30页 + 后30页**（共60页）
- 或**全部源代码**（不足60页时）
- 例外交存方式：
  - 覆盖机密部分（不超过50%）
  - 前10页 + 任意连续50页等

### 文档鉴别材料（说明书）

- **前30页 + 后30页**（共60页）
- 或**全部说明书**（不足60页时）

## 六、权属证明文件

| 开发情况 | 所需证明文件 |
|---------|------------|
| **自主开发** | 无需额外证明 |
| **委托开发** | 委托开发合同 |
| **合作开发** | 合作开发协议（明确权属划分） |
| **职务作品** | 单位证明文件 |
| **转让/继承** | 转让/继承合同 + 原软著证书 |

## 七、申请流程与时间

### 流程步骤

1. **注册账号**（[ccopyright.com.cn](https://www.ccopyright.com.cn/)）
2. **实名认证**
3. **填写申请表**
4. **上传鉴别材料**（源代码 + 说明书，PDF 或 Word 格式）
5. **上传证明材料**
6. **在线缴费**
7. **提交申请**
8. **形式审查**（5个工作日内）
9. **实质审查**（45-55个工作日）
10. **领取证书**

### 时间和费用

| 办理方式 | 审查周期 | 费用参考 |
|---------|---------|---------|
| **普通申请** | 60个工作日（约3-6个月） | 290-300元 |
| **加急（30天）** | 30个工作日 | 450-600元 |
| **加急（7天）** | 7个工作日 | 需额外付费 |

## 八、常见驳回原因及预防

### 源代码相关

| 驳回原因 | 具体表现 | 预防措施 |
|---------|---------|---------|
| **代码量不足** | 每页行数少于50行，空行/注释计入 | 删除空行和注释，确保每页≥50行有效代码 |
| **格式不规范** | 字号过大、页眉缺失或与申请表不一致 | 严格按排版规范执行，提交前逐页核查 |
| **连续性破坏** | 前30页/后30页中间有缺页 | 确保前后各30页内容完整连续 |
| **代码相似度高** | 大量复制开源代码或与已登记软件雷同 | 确保核心功能代码为自主开发，不超过20%框架代码 |

### 申请表相关

- **名称不一致**：申请表与源代码/说明书页眉名称不同 → **三处名称必须完全一致**
- **版本号格式错误**：如写成"1.0"而非"V1.0" → **统一使用V+数字格式**
- **日期填写错误**：开发完成日期晚于首次发表日期 → **严格遵守日期逻辑关系**
- **功能描述与代码不符**：描述了代码中未实现的功能 → **逐一对照核实**

### 材料缺失

- **证明材料缺失**：企业申请未加盖公章、未签字 → 提交前逐项核对材料清单
- **说明书不符**：页数不足、缺少截图或截图模糊 → 按页数要求补充，确保截图清晰

### 软件名称问题

- **名称过于通用**：如"管理系统V1.0"无法区分 → 加入品牌或行业特征词
- **名称重复**：与已登记软件完全相同 → 提前在平台检索确认名称唯一性

## 九、申请前自检清单

提交前请逐项确认以下内容：

- [ ] 源代码前30页从程序入口/起始处开始，内容连续
- [ ] 源代码后30页包含程序结束标志，内容连续
- [ ] 源代码每页有效代码行数 **≥ 50行**（空行和注释已删除）
- [ ] 源代码字号 **≤ 13号**，使用等宽字体，行距固定12磅
- [ ] 源代码**页眉**标注软件名称+版本号，与申请表完全一致
- [ ] 源代码**页码**格式正确（第X页 共60页），连续编排
- [ ] 说明书页数满足最低要求（≥15页或≥20页）
- [ ] 说明书包含完整截图，每2-3页至少一张，截图清晰
- [ ] 说明书**页眉**软件名称+版本号与申请表完全一致
- [ ] 说明书有封面和目录（不计入页数）
- [ ] 申请表软件全称格式正确（含品牌+功能+软件+版本号）
- [ ] 申请表功能描述字数在 **500-1300字** 之间，与代码实现一一对应
- [ ] 开发完成日期 **≤** 首次发表日期 **<** 申请日期
- [ ] 身份证明材料完整（企业：营业执照+公章+签名；个人：身份证+签字）
- [ ] 所有材料软件名称、版本号**三处完全一致**（申请表、源代码页眉、说明书页眉）
