# 腾讯云 TRTC SDK 调研报告

## 一、产品概述

腾讯云实时音视频（TRTC，Tencent Real-Time Communication）是腾讯基于多年音视频技术积累推出的 PaaS 服务，主打**低延时互动直播**和**多人音视频通话**两大场景，覆盖手机、桌面、Web、微信小程序全平台。

与本项目的匹配度：TRTC 是目前**微信小程序生态内唯一可用的成熟实时音视频方案**，原生支持 `<live-pusher>` / `<live-player>` 微信组件，无需额外适配。

---

## 二、微信小程序集成方式

### 2.1 底层原理

TRTC 微信小程序方案不依赖传统的 WebRTC，而是基于微信原生的两个组件：

| 组件 | 功能 |
|------|------|
| `<live-pusher>` | 推流端：采集本地摄像头/麦克风，推送音视频流至腾讯云 |
| `<live-player>` | 拉流端：从腾讯云拉取远端音视频流进行播放 |

通过 `trtc-wx` npm 包管理 TRTC 房间状态、进房/退房/推流/拉流等生命周期。

### 2.2 环境要求

| 条件 | 要求 |
|------|------|
| 微信基础库 | ≥ 2.10.0 |
| 微信 App 版本 | ≥ 7.0.9 |
| 小程序类目 | 需具备 live-pusher/live-player 权限的类目（**医疗类目可开通**） |
| 服务器域名 | 需在小程序后台配置 TRTC 相关域名白名单 |

### 2.3 权限开通步骤

1. 注册腾讯云账号 → 开通 TRTC 服务 → 创建应用获取 `SDKAppID` 和密钥
2. 小程序管理后台 → 开发 → 接口设置 → 开通 live-pusher 和 live-player 组件权限
3. 安装 `trtc-wx` npm 包 → 初始化 SDK → 进房 → 推拉流

### 2.4 与 uni-app 的兼容性

uni-app 在编译为微信小程序时，直接使用微信原生 `<live-pusher>` / `<live-player>` 组件，`trtc-wx` SDK 可直接引入使用。无需额外适配层。

## 三、核心能力与本项目需求匹配

| 背调需求 | TRTC 能力 | 匹配度 |
|---------|----------|:--:|
| "一键发起"音视频指导 | `enterRoom()` + `startPush()` API，支持编程式快速进房 | ✅ 完全匹配 |
| "实时音视频接入" | 超低延迟（<300ms），全球专线网络 | ✅ |
| "同步床边示教"（实时共享画面） | 后置摄像头推流，实时传输现场画面 | ✅ |
| "截屏或录屏" | 云端录制（REST API触发）+ 云端截图 | ⚠️ 录制通过 API 触发，非客户端操作 |
| "多终端切换"（小程序 ↔ PC 后台） | 多端 SDK 统一房间管理，同一用户可在不同端进同一房间 | ✅ |
| "预约与排班" | 不直接提供，需业务层实现 | ❌ 业务层功能 |
| "加急强提醒" | 不直接提供，需配合微信订阅消息 | ❌ 业务层功能 |
| "患者信息自动脱敏" | 可叠加云端水印（"请勿截图外传"），脱敏逻辑需业务层实现 | ⚠️ 水印支持 |
| 专家 PC 端高清影像查看 | Web SDK 支持高清视频流 + 屏幕共享 | ✅ |

## 四、关键技术细节

### 4.1 房间管理

- 房间 ID 由业务方自定义（uint32 类型或字符串类型）
- 同一用户可在不同设备进入同一房间（多端切换场景）
- 支持 REST API 查询房间内用户列表、解散房间、移除用户

### 4.2 云端录制

- 通过 REST API (`CreateCloudRecording`) 启动/停止录制
- 支持**单流录制**（每人一个文件）和**混流录制**（合并为一个文件）
- 录制文件自动存入腾讯云 COS 或 VOD（云点播）
- 成本：录制时长按分钟计费，叠加存储费用

**对本项目的意义**：查房结束后自动生成带教记录，无需医师手动操作。

### 4.3 云端截图

- 通过 REST API 对指定流进行截图，生成图片存入 COS
- 可用于"操作回溯"——记录关键画面

### 4.4 水印

- 混流时支持叠加图片水印（最多 25 个）
- 可用于视频画面叠加"请勿截图外传"等合规提示

### 4.5 画质与码率

| 档位 | 分辨率 | 码率 | 适用场景 |
|------|--------|------|---------|
| 标清 SD | 640×360 | 400 kbps | 弱网/省流 |
| 高清 HD | 1280×720 | 800 kbps | 常规视频通话 |
| 全高清 FHD | 1920×1080 | 1500 kbps | PC 端高清查看 |

> 支持自适应码率（QoS），根据网络质量自动升降档。

### 4.6 并发限制

- 单房间最大并发：无硬性上限（取决于流数×码率总带宽）
- 推流路数：建议同一房间内 ≤ 50 路同时推流（超出后需使用 MCU 混流）

对于本项目"远程查房"场景（1v1 或 1vN 小范围），远在限制之内。

## 六、竞品对比

| 维度 | 腾讯 TRTC | 阿里云 ARTC | 声网 Agora |

## 七、风险与注意事项

| 风险 | 说明 | 缓解 |
|------|------|------|
| **医疗类目审核** | `<live-pusher>` 组件权限需医疗类目 | **由成都市卫生部门统一申报，审核通过率极高**，但仍需预留流程时间 |
| **包月套餐强制绑定** | 小程序必须购买包月套餐才能使用，免费版仅 7 天 | 预算中预留年费 |
| **弱网环境** | 基层卫生院 3G/4G 网络可能影响通话质量 | 自适应码率 + 最低标清 360p 兜底；TRTC 在 3G 下可保证音频通话 |
| **设备兼容性** | 低端 Android 手机可能不支持高清推流 | POC 阶段真机矩阵测试 |
| **成本突增风险** | 使用量超预期时按量计费可能超预算 | 设置日消费上限告警；预估用量留 30% buffer |
| **TRTC 服务中断** | 依赖腾讯云单点 | 腾讯云 SLA 99.95%；跨可用区部署 |

## 八、POC 验证建议

建议在开发准备期（前 2 周）完成以下验证：

1. **基础音视频**：1v1 通话，验证进房/退房/推流/拉流全流程
2. **弱网测试**：模拟 3G（300kbps）/ 4G（2Mbps）/ WiFi 三种网络环境
3. **真机兼容**：3 款低端 Android + 2 款主流 iOS + 1 款旧版 iPhone
4. **云端录制**：启动录制 → 生成文件 → COS 回放全链路
5. **截屏功能**：API 触发截图 → 图片回显
6. **uni-app 集成**：trtc-wx SDK 在 uni-app 编译为微信小程序后的调用验证

## 九、结论

TRTC 是"成都市基层卫生云服务平台"实时音视频需求的**唯一可行选择**，理由：

1. 微信小程序生态内，仅 TRTC 基于原生 `<live-pusher>` / `<live-player>` 组件实现，其他方案均需 WebView 桥接
2. 功能覆盖背调全部实时音视频需求（通话、示教、录制、截图、多端切换）
3. 成本可控（基础版 625 元/月即可覆盖预估用量）
4. 团队无需学习额外的音视频技术栈，SDK 集成成熟
