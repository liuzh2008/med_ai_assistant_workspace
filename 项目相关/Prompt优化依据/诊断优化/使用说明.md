# 诊断分析数据提取与对比文档生成 - 使用说明

**用途**：从生产库提取"诊断分析"记录（AI 诊断 + 诊断依据）与"目前诊断"（医生最终诊断），
摆渡回开发环境后生成对比文档，为 Prompt 模板优化提供支撑。

**状态**：脚本已在本机开发库（Oracle 23ai Free）与测试库验证通过，可直接交付生产执行。

---

## 一、文件清单

| 文件 | 作用 |
|------|------|
| `extract_01_count.sql` | 步骤1：数据量摸底（执行前确认数量与内容长度） |
| `extract_02_results.sql` | 步骤2：导出诊断分析记录（AI诊断+依据原文，脱敏后） |
| `extract_03_diagnoses.sql` | 步骤3：导出目前诊断（医生最终诊断，脱敏后；**末位含 ICD10Code 字段**） |

| `build_icd_dict.py` | **词典主构建器**：全量 ICD-10 国临版2.0 + 同义词归一化 + 算法筛查 + 人工校正表 |
| `build_dict_skeleton.py` | 词典辅助（可选）：AI 名→医生标准名桥接骨架 + 人工审核清单（无 ICD 库时的过渡方案） |
| `fill_icd_codes.py` | 词典辅助（可选）：从生产 `DIAGNOSIS.ICD10Code` 回填编码的替代路径 |

| `诊断编码词典_统计报告.md` | 匹配率统计 + 未映射清单 + **Prompt 注入清单**（Top150 高频名） |
| `诊断编码词典_未映射清单.xlsx` | 785 条算法无法映射条目（检验/影像型表述为主），供人工补码 |
| `医生标准名清单.json` | 671 个医生标准诊断名 |
| `sample_local/` | 本机开发库数据生成的示例产物（格式参考） |

## 二、生产环境执行步骤（提取侧）

1. 将本目录整个拷贝到生产服务器（或可连接生产库的机器）。
2. 修改 `run_extract.bat` 中的连接串：
   ```bat
   set CONN=用户名/密码@//主机:端口/服务名
   ```
   建议使用**只读账号**；若无，使用部署配置（`.env` / `application-prod`）中的库账号。
3. 双击 `run_extract.bat`（或手动依次执行 3 个 SQL）。
4. 检查步骤1输出：确认记录数合理、`max_len` 小于 30000。
   - 若 `max_len` 超过 30000，需改用其他导出方式（联系开发人员）。
5. 取走本目录下生成的 2 个文件：
   - `diagnosis_analysis_records.txt`
   - `current_diagnoses.txt`
6. **从生产服务器删除这两个导出文件**（含数据，用后即清）。

### 关键注意事项

- **NLS_LANG 必须设置**：`SIMPLIFIED CHINESE_CHINA.AL32UTF8`。不设置会导致中文
  LIKE 匹配失败（模板名过滤为空，导不出数据）。`run_extract.bat` 已内置。
- 提取全程为**只读查询**，不写任何生产数据。
- 导出文件编码为 UTF-8。

## 三、数据安全说明

导出内容**不含**患者姓名、身份证号、手机号、医保号等 PII：

| 处理 | 说明 |
|------|------|
| PatientID 加盐哈希 | SHA-256（盐 `MEDAI_DIAG_EXTRACT`），截取前 16 位，无法反推 |
| AI 诊断依据 | AI 生成文本，仅含检验指标值等临床信息，无患者身份信息 |
| 医生诊断文本 | 仅诊断名称文本 |

仍请注意：文件在摆渡过程中按团队医疗数据安全规范保管，仅限开发环境分析使用。

## 四、开发环境生成对比文档（解析侧）

```powershell
cd temp\diagnosis-extract
python parse_and_generate.py
```

前提：两个 txt 文件与本脚本同目录，且 Python 环境有 `openpyxl`。

产出：
- `诊断分析对比报告_YYYYMMDD.md`：概览统计、模板缺陷线索聚合、被修改/未采纳/
  医生新增/直接采纳分组明细。
- `诊断分析对比明细_YYYYMMDD.xlsx`：一行一条 AI 诊断的全量明细 + AI诊断聚合统计表。

建议将正式产物归档到 `doc/迭代/诊断分析优化/`，作为模板优化依据。

## 五、判定规则（沿用《AI诊断数据采集方案》）

AI 诊断名与目前诊断列表逐一计算 Levenshtein 相似度（归一化去空格标点后）：

| 相似度 | 判定 | 含义 |
|--------|------|------|
| = 1.0 | 直接采纳 | AI 输出与医生最终命名一致 |
| 0.45 ~ 1.0 | 被修改 | AI 方向对但命名不精确（**价值最高的线索**） |
| < 0.45 | 未采纳 | AI 多写/无关诊断，或命名差异过大 |
| 医生有、AI 无 | 医生新增 | AI 遗漏，模板缺失线索（条次计数，同一患者多次分析会累计） |

## 六、已知局限（人工复核时注意）

1. **Levenshtein 无法识别缩写/全称同义**：如"冠状动脉粥样硬化性心脏病" vs "冠心病"
   会判为未采纳。报告中的"最接近的医生诊断"仅供快速定位，判定需人工复核。
2. **DIAGNOSIS 表只有当前最终态**：目前诊断取的是患者当下的最终诊断（非分析时刻快照），
   这正是模板优化的金标准（AI 应接近医生最终采纳的命名）。
3. **同一患者多次分析**：每次分析均单独对比同一份最终诊断，重复执行的记录会放大
   统计（可在 Excel 中按患者+时间过滤）。
4. **旧版模板输出格式兼容**：解析器兼容三种 AI 输出格式（标准"### 诊断列表"块 /
   "诊断名称:"标记 / 旧版"1. **诊断名**:"编号列表），旧格式无诊断依据内容。

## 七、诊断编码词典构建（AI 诊断名 → ICD-10 国临版2.0 标准名/编码）

**目的**：AI 诊断分析输出的诊断名经常不符合 ICD-10 编码口径（缩写、口语化、非标准组合、
检验/影像表述直接当诊断名），需要「AI 诊断名 → 国临版标准名 → ICD 编码」对照词典，用于：
- Prompt 模板优化：把高频 AI 诊断名的标准表述与编码注入模板命名规范段；
- 分析判定：量化"AI 诊断 ICD 合规率"，定位不合规高频诊断名。

**数据源**：`ICD库_国临版2.0.json`（国家临床版2.0，35862 条，含 `I48.x01` 扩展码，
来源：gitcode 公开镜像 `open-source-toolkit/44edd` 的 7z/xlsx，已导出为 JSON 入库）。

**执行**：
```powershell
python build_icd_dict.py                 # 复用现有 ICD 库
python build_icd_dict.py <国临版2.0.xlsx路径>   # 首次：从 xlsx 导出库
```
产出 `诊断编码词典.json`、`诊断编码词典_统计报告.md`（含 Prompt 注入清单）、
`诊断编码词典_未映射清单.xlsx`。

**算法口径（build_icd_dict.py 内置）**：
1. **同义词/术语归一化**（双向作用于查询名与 ICD 名）：`主动脉瓣反流→关闭不全`、
   `左房增大→左房扩大`、`早搏→期前收缩`、`脑梗(非梗死)→脑梗死`、`混合型→混合性`、
   `血脂异常→高脂血症`、`糖耐量异常→糖耐量受损` 等；
2. **匹配链**：精确（主名/别名）→ 人工校正表 → 医生锚点 → 包含（长度差+修饰词惩罚）
   → 模糊（同首字符桶 difflib ≥0.82）；
3. **人工校正表**：国临版无对应/易误配的高频名（如 `肝功能异常→K72.905 肝功能不全`、
   `高血压病→I10.x09 原发性高血压`、`很高危→极高危`、`贫血（轻度）→D64.901`），
   每条附"为什么这么编"的备注；
4. **置信度**：exact/医生锚点=high，校正表=medium（编码人工确认过），
   包含/模糊=low（0.45~0.8 相似度有"张冠李戴"风险，须人工复核）。

**未映射的 785 个 AI 名**（覆盖约 4.9% 条数）多数是**检验结果/影像描述型表述**
（如"糖化血红蛋白升高""高密度脂蛋白胆固醇升高""脑白质脱髓鞘变"）或**术后状态**，
本就不应作为疾病诊断名输出——这是模板优化的直接线索：禁止把检查指标/影像发现当诊断名。

**替代路径（可选）**：若希望采用医院自身编码口径，用更新后的 `extract_03_diagnoses.sql`
（末位 ICD10Code 字段）从生产重导 `current_diagnoses.txt`，再运行 `fill_icd_codes.py`
按医生标准名回填编码，与国临版结果比对校准。

**Prompt 注入**：`诊断编码词典_统计报告.md` 第四节给出 Top150 高频名
（覆盖 95%+ 条数）→ 标准名+编码 对照表，直接作为诊断分析模板"命名规范"段附录。
