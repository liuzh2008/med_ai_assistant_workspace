# 诊断分析数据提取与对比文档生成 - 使用说明

**用途**：从生产库提取"诊断分析"记录（AI 诊断 + 诊断依据）与"目前诊断"（医生最终诊断），
摆渡回开发环境后生成对比文档，为 Prompt 模板优化提供支撑。

**状态**：脚本已在本机开发库（Oracle 23ai Free）与测试库验证通过，可直接交付生产执行。

---

## 一、文件清单

| 文件 | 作用 |
|------|------|
| `extract_01_count.sql` | 步骤1：数据量摸底（执行前确认数量与内容长度） |
| `extract_02_results.sql` | 步骤2：导出诊断分析记录（AI诊断+依据原文，脱敏后） |
| `extract_03_diagnoses.sql` | 步骤3：导出目前诊断（医生最终诊断，脱敏后） |
| `run_extract.bat` | Windows 一键执行入口（需先改连接串） |
| `parse_and_generate.py` | 开发环境解析脚本：生成 Markdown 报告 + Excel 明细 |
| `sample_local/` | 本机开发库数据生成的示例产物（格式参考） |

## 二、生产环境执行步骤（提取侧）

1. 将本目录整个拷贝到生产服务器（或可连接生产库的机器）。
2. 修改 `run_extract.bat` 中的连接串：
   ```bat
   set CONN=用户名/密码@//主机:端口/服务名
   ```
   建议使用**只读账号**；若无，使用部署配置（`.env` / `application-prod`）中的库账号。
3. 双击 `run_extract.bat`（或手动依次执行 3 个 SQL）。
4. 检查步骤1输出：确认记录数合理、`max_len` 小于 30000。
   - 若 `max_len` 超过 30000，需改用其他导出方式（联系开发人员）。
5. 取走本目录下生成的 2 个文件：
   - `diagnosis_analysis_records.txt`
   - `current_diagnoses.txt`
6. **从生产服务器删除这两个导出文件**（含数据，用后即清）。

### 关键注意事项

- **NLS_LANG 必须设置**：`SIMPLIFIED CHINESE_CHINA.AL32UTF8`。不设置会导致中文
  LIKE 匹配失败（模板名过滤为空，导不出数据）。`run_extract.bat` 已内置。
- 提取全程为**只读查询**，不写任何生产数据。
- 导出文件编码为 UTF-8。

## 三、数据安全说明

导出内容**不含**患者姓名、身份证号、手机号、医保号等 PII：

| 处理 | 说明 |
|------|------|
| PatientID 加盐哈希 | SHA-256（盐 `MEDAI_DIAG_EXTRACT`），截取前 16 位，无法反推 |
| AI 诊断依据 | AI 生成文本，仅含检验指标值等临床信息，无患者身份信息 |
| 医生诊断文本 | 仅诊断名称文本 |

仍请注意：文件在摆渡过程中按团队医疗数据安全规范保管，仅限开发环境分析使用。

## 四、开发环境生成对比文档（解析侧）

```powershell
cd temp\diagnosis-extract
python parse_and_generate.py
```

前提：两个 txt 文件与本脚本同目录，且 Python 环境有 `openpyxl`。

产出：
- `诊断分析对比报告_YYYYMMDD.md`：概览统计、模板缺陷线索聚合、被修改/未采纳/
  医生新增/直接采纳分组明细。
- `诊断分析对比明细_YYYYMMDD.xlsx`：一行一条 AI 诊断的全量明细 + AI诊断聚合统计表。

建议将正式产物归档到 `doc/迭代/诊断分析优化/`，作为模板优化依据。

## 五、判定规则（沿用《AI诊断数据采集方案》）

AI 诊断名与目前诊断列表逐一计算 Levenshtein 相似度（归一化去空格标点后）：

| 相似度 | 判定 | 含义 |
|--------|------|------|
| = 1.0 | 直接采纳 | AI 输出与医生最终命名一致 |
| 0.45 ~ 1.0 | 被修改 | AI 方向对但命名不精确（**价值最高的线索**） |
| < 0.45 | 未采纳 | AI 多写/无关诊断，或命名差异过大 |
| 医生有、AI 无 | 医生新增 | AI 遗漏，模板缺失线索（条次计数，同一患者多次分析会累计） |

## 六、已知局限（人工复核时注意）

1. **Levenshtein 无法识别缩写/全称同义**：如"冠状动脉粥样硬化性心脏病" vs "冠心病"
   会判为未采纳。报告中的"最接近的医生诊断"仅供快速定位，判定需人工复核。
2. **DIAGNOSIS 表只有当前最终态**：目前诊断取的是患者当下的最终诊断（非分析时刻快照），
   这正是模板优化的金标准（AI 应接近医生最终采纳的命名）。
3. **同一患者多次分析**：每次分析均单独对比同一份最终诊断，重复执行的记录会放大
   统计（可在 Excel 中按患者+时间过滤）。
4. **旧版模板输出格式兼容**：解析器兼容三种 AI 输出格式（标准"### 诊断列表"块 /
   "诊断名称:"标记 / 旧版"1. **诊断名**:"编号列表），旧格式无诊断依据内容。
