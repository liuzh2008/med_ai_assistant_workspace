# 医疗AI助手系统 — 项目介绍

> 让基层医院用得起、用得好的AI医疗辅助平台

---

## 一、医疗信息化痛点与我们的解决方案

### 1.1 当前医疗信息化面临的核心问题

| 痛点 | 现状 | 带来的后果 |
|------|------|-----------|
| **诊断编码不完整** | 医生凭经验编码，并发症/合并症易遗漏 | DRG分组不准确，医保收益流失 |
| **DRG管理粗放** | 缺乏实时分组与盈亏分析工具 | 医保付费改革下收入持续下降 |
| **质控工作量大** | 质控指标靠人工逐案筛查 | 漏检率高、人力消耗大 |
| **病历书写效率低** | 依赖键盘逐字录入，格式不规范 | 占用大量临床时间，影响诊疗 |
| **信息孤岛严重** | HIS/LIS/PACS各自独立，数据不互通 | 医生缺乏患者全景视图，决策依据不全 |
| **AI门槛高** | 传统AI系统动辄百万投入，大医院专属 | 基层医院无力承担，数字鸿沟加大 |
| **数据安全顾虑** | 患者隐私数据上传云端风险大 | 合规风险，医院不敢用AI |

### 1.2 我们的解决思路

**核心理念：AI增强临床决策，而非替代医生判断**

- **低成本** — 硬件投入仅需5~10万元，容器化一键部署
- **强安全** — 患者敏感数据本地加密，"最小必要化"原则上传云端
- **全流程** — 覆盖住院部从入院到出院的完整诊疗流程
- **临床导向** — 由心内科医生主导设计，充分贴合临床实际需求

## 二、系统架构

### 2.1 双服务器分离架构

```
┌──────────────────────────────────────────┐
│          前端应用（Vue 3）                │
│   Web浏览器访问 · 响应式设计（PC/平板）   │
└───────────────────┬──────────────────────┘
                    │ HTTPS
                    ▼
┌──────────────────────────────────────────┐
│       主服务器（Spring Boot 3.x）        │
│                                          │
│  · 业务逻辑处理     · REST API接口       │
│  · 患者数据管理     · 任务调度管理        │
│  · 与医院HIS/LIS对接                     │
└───────────────────┬──────────────────────┘
                    │ 加密通道 / 轮询机制
                    ▼
┌──────────────────────────────────────────┐
│       执行服务器（Spring Boot 3.x）      │
│                                          │
│  · AI大模型调用引擎  · Prompt组装与管理   │
│  · 长耗时任务异步处理 · 重试与熔断机制    │
└──────────────────────────────────────────┘

┌──────────────────────────────────────────┐
│             数据存储层                    │
│  Oracle数据库 · Redis缓存（可选）         │
└──────────────────────────────────────────┘
```

**架构核心优势：**

- **性能隔离** — AI计算任务不阻塞用户日常操作
- **故障隔离** — 执行服务异常不影响业务系统可用性
- **独立扩展** — 主服务与执行服务可各自水平扩展
- **灵活部署** — 支持单院部署和区域中心模式

### 2.2 技术栈概览

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| **前端** | Vue 3 + Element Plus | 现代响应式框架，企业级UI |
| **后端** | Spring Boot 3 + Java 21 | 最新LTS版本，性能优异 |
| **数据库** | Oracle 21c | 企业级数据库 |
| **AI引擎** | DeepSeek Chat / 阿里百炼 | 多模型灵活切换 |
| **语音** | 阿里云ASR | 实时语音识别，延迟<1秒 |
| **部署** | Docker容器化 | 一键启动，快速部署 |

### 2.3 容器化部署

- Docker Compose一键编排全套服务
- 支持Windows/Linux双平台部署
- 环境变量统一管理，配置与代码分离
- 健康检查 + 自动重启策略
- 数据卷持久化，保障数据安全

## 三、安全性设计

### 3.1 多层安全防护体系

```
┌─────────────────────────────────────────────┐
│              第一层：网络安全                 │
│  HTTPS/TLS加密传输 · 防火墙配置 · 访问控制   │
├─────────────────────────────────────────────┤
│              第二层：应用安全                 │
│  Spring Security · JWT令牌 · 会话超时控制     │
├─────────────────────────────────────────────┤
│              第三层：数据安全                 │
│  AES-256-CBC加密 · 敏感数据脱敏 · 审计日志    │
├─────────────────────────────────────────────┤
│              第四层：接口安全                 │
│  参数校验 · 错误码规范 · 限流控制             │
└─────────────────────────────────────────────┘
```

### 3.2 核心安全机制

**数据加密传输**
- 采用AES-256-CBC加密算法（PBKDF2密钥派生）
- 主服务器加密 → 加密中转表 → 执行服务器解密
- 每次加密生成随机IV，同一数据加密结果每次不同
- 患者敏感信息"最小必要化"原则，不明文上传云端

**身份认证与授权**
- 支持OIDC、JWT、Basic多种认证模式
- Argon2密码散列（安全强度远高于MD5/SHA）
- 基于角色的权限管理（RBAC）
- 会话超时自动退出

**数据安全治理**
- 软删除机制，所有操作可追溯
- 操作日志完整审计
- 乐观锁并发控制
- 数据范围校验，保障患者隐私边界

### 3.3 合规性

- 遵循《个人信息保护法》相关要求
- 患者隐私数据加密存储和传输
- 所有AI分析结果标注"本内容由AI生成，仅供参考"
- 支持数据审计和追溯

## 四、功能介绍

### 4.1 AI诊疗辅助系统 ⭐核心功能

**功能概述：** 将患者病历、诊断、检验检查等数据智能组装为Prompt，调用大语言模型进行分析，为医生提供诊断建议、治疗方案参考。

- **Prompt智能组装** — 内置多种模板（诊断分析、治疗建议、风险评估），支持自定义
- **多模型支持** — DeepSeek Chat、阿里百炼等，灵活切换
- **流式响应** — 实时返回生成结果，无需长时间等待
- **结果管理** — 存储历史分析结果，医生可编辑反馈

> 演示要点：选择患者 → 查看AI生成的诊断分析 → 展示Prompt模板管理

---

### 4.2 DRG智能分析系统 ⭐重点功能

**功能概述：** 基于患者诊断和手术信息，自动匹配DRG分组，计算医保盈亏，辅助医保精细化管理。

**核心能力：**
- **DRG自动匹配** — ICD精确匹配 → 名称双向包含 → 相似度智能匹配（≥0.7）
- **双向严格分流** — 有手术/无手术患者分别匹配对应DRG组
- **盈亏实时计算** — 实时对比医保支付标准与实际费用
- **HIV安全过滤** — 患者无HIV诊断时自动排除HIV相关分组

> 演示要点：选择患者 → 查看DRG自动匹配结果 → 查看盈亏分析

---

### 4.3 MCC/CC并发症智能筛查

**功能概述：** 基于12,000+条MCC字典，自动筛查患者可能的严重并发症/合并症（MCC）和一般并发症/合并症（CC），提升诊断编码完整率。

- **编码精确匹配** + **名称相似度匹配**（Levenshtein算法）
- **排除规则自动检查** — 避免误匹配
- **分组排序展示** — 按来源诊断分组，MCC优先于CC
- **性能优异** — 内存缓存，筛查耗时<100ms

> 演示要点：查看患者MCC/CC筛查结果 → 展示候选并发症列表

---

### 4.4 语音识别与病历书写辅助

**功能概述：** 支持医生通过语音实时录入病历，AI辅助整理格式，大幅提升病历书写效率。

| 模式 | 方式 | 场景 |
|------|------|------|
| **实时语音识别** | WebSocket长连接 | 医生查房时现场语音输入 |
| **录音文件识别** | HTTP文件上传 | 录音后批量识别 |

- 延迟<1秒，支持中英文混合识别
- 识别结果可直接写入病历

> 演示要点：点击录音按钮 → 语音输入 → 查看实时转写结果

---

### 4.5 病历记录转待办事项

**功能概述：** 系统自动分析当日病历内容，识别待办事项（如"复查X光"、"调整用药"），生成结构化待办清单。

- 支持按科室、日期范围筛选
- 仅包含在院患者
- AI分析生成待办清单（床号、姓名、待办事项、原因）
- 减少遗漏，规范诊疗流程

> 演示要点：查看待办事项列表 → 展示AI生成的待办清单

---

### 4.6 医院数据同步系统

**功能概述：** 与医院现有HIS/LIS/EMR系统对接，自动同步患者数据。

- **患者基本信息同步** — 科室、床号、诊断、医嘱
- **检验检查结果同步** — LIS数据、影像报告
- **病历内容同步** — EMR病历记录
- **SQL模板管理** — 可配置化查询，适配不同HIS系统
- **定时自动同步** — 无需人工干预

---

### 4.7 患者数据管理

- 患者基本信息、在院状态、科室列表
- 诊断管理（ICD-10编码、主次诊断标记）
- 病历管理（创建、查询、格式化）
- 检验检查结果查看
- 医嘱管理（长期/临时医嘱格式化展示）

---

### 4.8 监控与运维

- 系统健康检查（主服务器、执行服务器、数据库）
- JVM内存/CPU监控
- AI调用成功率和响应时间统计
- 数据库连接池状态监控
- 错误日志告警

## 六、适用对象与合作模式

### 6.1 目标用户

| 用户角色 | 主要使用功能 | 核心价值 |
|---------|------------|---------|
| 临床医生 | AI诊断辅助、语音病历、待办事项 | 提升诊疗效率，减少漏诊 |
| 科室管理者 | DRG分析、MCC筛查、盈亏计算 | 精细化成本管理 |
| 医保管理人员 | DRG分组分析、费用预测 | 支持医保付费改革 |
| 质控人员 | AI辅助质控分析 | 提升质控效率 |
| 系统管理员 | 系统监控、配置管理 | 保障系统稳定运行 |

### 6.2 部署成本

- **硬件投入**：5~10万元（对比传统AI系统数百万）
- **运维成本**：1名IT人员即可维护
- **部署方式**：Docker容器化，一键部署
- **部署周期**：1~2周即可上线运行

### 6.3 部署模式

- **单院模式** — 医院内网独立部署，数据不出院
- **区域中心模式** — 区域中心部署，基层医院远程调用
