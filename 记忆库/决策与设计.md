### 2026-08-14 诊断临床规则注入：白名单仅"诊断分析" + 规则同步两跳链路确认
- **决策**：`combinePromptContent` 收口注入的白名单收紧为 `Set.of("诊断分析")`（不含"诊断审查"）——Gate 2 审查 Prompt 由 `DiagnosisReviewListener` 组装（objectiveContent 末尾已含 `ClinicalExperienceProvider` 注入段）且同样走 `submitPromptInternal → combinePromptContent`，白名单含"诊断审查"会导致同一 Prompt 双份规则段。Gate 2 现有链路匹配源为 AI 输出、禁区特征词可命中，功能不缺失。
- **架构事实（两跳规则同步）**：`ClinicalRuleSyncService`（`@Profile("execution")`）从 GitHub 拉规则到 `RemoteClinicalRuleCache` 内存缓存，**不写 DB**；主服务器 DB 由 `ClinicalRuleUpdateService`（`@Profile("main")`）经 `POST /api/clinical-rules/sync`（异步 taskId 轮询）从执行服务器 API 拉全量后逐条 UPSERT（keywordMatch 匹配、版本相同跳过）。
- **架构事实（模板表无自动同步）**：运行时 Prompt 模板从主服务器 `PROMPT_TEMPLATES` 表读取（`promptTemplateRepository.findByPromptTypeAndPromptName`）；GitHub `prompt-templates/` 文件仅作版本库，模板补丁需双改（GitHub 文件 + `PUT /api/ai/updatePromptTemplate` 更新 DB 表）。
- **关联**：《诊断分析临床规则注入实施计划.md》（doc/迭代/诊断分析优化/）。

### 2026-08-14 DSH 安全评估要点（Idea 验证阶段，已向用户给出完整清单）

- **验证阶段安全基线**：只用本地脱敏测试库（211 条镜像，禁生产）、验证实例禁 shell/代码/web 工具、MCP 只读工具+输出脱敏、主机防火墙限制 DSH 出网（只放模型 API+后端）、关遥测、会话按患者分开、API key 限额。

### 2026-08-14 脱敏双层防护决策：LLM 调用前出口兜底（用户提出，已采纳）
- **问题**：DSH 调 LLM 前必须脱敏；数据进 LLM 的通道不止工具结果——用户输入（口述姓名）、文件/技能内容、会话历史都可能带 PII，仅网关输出脱敏（数据面）不够。
- **决策**：双层防护——第 1 层源头脱敏（MCP 网关字段白名单+映射，已设计）；第 2 层 **LLM 出口脱敏插件**（DSH 侧 TS 插件，挂 `agent/pre-step` 改写消息 / `agent/request` waterfall 拦截）：确定性模式（身份证/手机/医保/住院号）正则掩码 + 姓名按网关下发映射表替换为泛化指代（"3床患者/患者P000123"）+ 残留不明 PII 阻断告警 + 审计每请求脱敏项数。
- **原则**：映射规则由 Java 网关维护下发（遵守"规则在 Java 侧"铁律）；性能用确定性正则+字典（不做 NER）；输入侧干净 → thinking/日志/回放全链无 PII。
- **关联**：方案文档 6.3 章、规范安全必检表已同步。

### 2026-08-13 DSH 插件化调研：四条接入通道与装载机制（结论速记）
- **背景**：调研能否把本项目各模块做成 DSH 插件；DSH 基线 47f943859b（工作副本 C:\Users\Administrator\Documents\Qoder\2026-08-13\chat-1\deepseek-harness）。
- **DSH 插件体系**：Cordis 组合框架（"everything is a plugin"）；工具插件最小形态 = npm 包导出 `{ name, inject:['tools'], apply(ctx){ ctx.tools.register(defineTool({...})) } }`（参考 docs/cookbook/adding-a-tool.md）。
- **外部插件装载**：profile 目录 `$DSH_HOME/profiles/<name>` 的 package.json dependencies + `cordis.patch.yml` 行；或 bundle 包声明 `dsh.bundle.patch` 后在 profile `bundles` 叠加；`dsh plugin --profile <name> add ./plugin` 自动维护 manifest（docs/user/develop/basic/publish.md）。
- **MCP 通道**：`@deepseek-ai/dsh-mcp-client`，每 server 一个 cordis.yml 行，支持 `stdio`/`streamable-http`（url+headers Bearer），工具名 `mcp__<serverName>__<rawName>`，`toolCallTimeoutMs` 默认 60s，仅桥接 tools（无 resources/prompts）。Java 侧可用 Spring AI MCP server 暴露 REST 能力。
- **Skill 通道**：`<projectRoot>/.dsh/skills`（rank 100）扫描 `<name>/SKILL.md`，frontmatter 需 name/description（kebab-case），模型加载器工具在 @deepseek-ai/dsh-tool-skill——本项目已用 junction 挂载 15 个技能，即此通道。
- **其他扩展点**：`ctx.commands`（人类命令）、`ctx.jobs`（后台任务）、`ConversationNodeDefinition`（Web 聊天节点，client 插件需 dsh.client 声明）、会话事件日志 `SessionEventMap`（持久化扩展）。
- **风险**：DSH 处于 developer preview、兼容性破坏变化频繁；UI 定制首选 client module 机制（package.json `dsh.client` + `exports["./client"]` + `ConversationNodeDefinition`，可无 fork 扩展，见 docs/subsystems/client-modules.md），深度改壳才走 fork 补丁路线（DSH-custom 档案已有流程）。
- **关联**：docs/architecture.md（"Where new behavior goes" 表）、packages/mcp/mcp-client/README.md、packages/boot/app-boot/README.md。

### 2026-08-13 AI诊断「改名后保留诊断依据」：行级绑定 + 四级显示匹配链
- **决策**：诊断依据展示从「按名称匹配」改为「行级绑定」——绑定以行的稳定标识（`d_<diagnosisId>` / `aim_<diagnosisId>` / `ai_<原始AI名归一化>`）为 key，与显示名称解耦；用户把同一诊断改成任何名称，绑定不丢。
- **显示匹配链**（`selectedDiagnosisBlock`）：行级绑定 → 归一化精确匹配 → 安全包含匹配（仅行名⊇块名，防"高血压"误配"高血压肾病"）→ 模糊匹配（Levenshtein ≥ 0.65，仅显示时 `allowFuzzy=true` 启用，命中带 `__fuzzy*` 标记并在依据上方显示黄色说明）。
- **原因**：名称可被改成任意值（如"高血压病3级 很高危"→"高血压病3级很高危"→无关名称），任何基于名称的缓存/匹配都无法保证改名后必然显示依据。
- **代码**：`med_ai_assistant_1.0_bs_vue/src/utils/diagnosisBlockMatch.js`（stableRowKey/buildRowBlockMap/resolveDiagnosisBlock）、`DiagnosisEditPanel.vue`（rowBlockMap + mergedDiagnosis watcher）、`diagnosisMerge.js`（buildRow 透传 `_originalName`）。
- **测试**：`npm run test:diagnosis` 31/31（test/diagnosis/diagnosisBlockMatch.test.mjs）。
