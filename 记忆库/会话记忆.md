## 2026-08-14（DSH 集成方案讨论：可靠性 + 查房场景）
- **可靠性两层框架**：传统可靠性（可用性/一致性/故障恢复）靠「旁路降级原则」——DSH/MCP 网关是增强旁路，挂了退化为现状（工作站直连 REST 不受影响）；Agent 行为可靠性（幻觉/串数据/不可复现）DSH 不解决，需自建四件套：地面事实强制（查询必须走工具）、溯源校验（结论指向依据数据）、确定性标注（事实 vs 建议分区）、审计回放（append-only 日志+注入医生身份）。一期验收六项：故障注入/幻觉回归集/长会话压缩/并发压力/崩溃恢复/升级演练。
- **MCP 关键配置**：`failOnStartupError` 默认 false（网关宕机时 DSH 静默零工具）→ 医疗场景必须设 true；`toolCallTimeoutMs` 默认 60s；重连预算耗尽后工具被注销不自动恢复 → 需自建"工具在位"健康监控并入现有告警体系。
- **查房场景成熟度拆解**（用户场景：口述安排冠脉造影→系统追问术前讨论/术前小结→自动写查房记录→提醒→审核保存）：会话内追问/流式生成/审批保存链路 ✅ DSH 原生（审批保存为二期写工具）；语音输入 ❌ DSH 无 ASR（全源码无 speech 能力），浏览器 Web Speech API 走 Google 不合规，需院内/离线 ASR + "语音转文本先确认再发送"；离屏提醒 ❌ 无推送通道，`dsh-schedule` 仅会话内投递（agent 空闲时开新 turn），需复用 AlertRuleService 接设备推送；保存需结构化落库 MedicalRecord + 审核 diff 留痕。定位为二期旗舰场景（查房 MVP：文本指令→取数→生成草稿→审批保存，语音/推送/手术写链后置）。
- **状态**：DSH 集成方案仍处 Idea 验证阶段，未实施；一期试点（患者/病历/检验查询 MCP 只读工具）待用户确认启动。

## 2026-08-13（DSH 远程设置 403 诊断会话）

- 现象：通过 http://100.66.1.3:3080/（Tailscale/CGNAT 地址，非回环）打开 DSH Web GUI 时，设置页「Agent 预设」「权限」面板报 `transport failure for /api/settings.describe: HTTP 403`。
- 根因：DSH 的 `/api` 浏览器信任围栏把 `settings.describe`/`settings.*`/`credentials.*`/`agentPreset.read|cop y|openDocument|remove`/`host.pickDirectory|openPath`/`llm.discoverModels` 列为特权方法，硬钉在 loopback（`PRIVILEGED_METHODS`，`packages/client/connection/src/index.ts`），非回环请求一律 403（`isTrustedApiRequest(request, [])`）；这是刻意的安全设计（配置平面在出现认证层前仅回环同源）。
- 处理：给 connection 插件新增配置 `allowRemotePrivilegedMethods`（默认 false）+ CLI flag `dsh --profile web --allow-remote-privileged-methods`，把特权方法钉扎放宽到 `trustedHosts` 声明的受信任 authority；只放宽这一处，外层 DNS-rebinding/跨站围栏不变。改动在 deepseek-harness checkout（C:\Users\Administrator\Documents\Qoder\2026-08-13\chat-1\deepseek-harness），涉及 connection 插件、web-app bundle（startup.ts/index.ts/cordis.patch.yml）、README（en/zh）、docs/config-catalog（已重新生成+配对）。测试 191 项通过。
- 远程使用方式：SSH 隧道 `ssh -L 3080:127.0.0.1:3080 user@server` 后开 http://127.0.0.1:3080 最稳妥；或绑定具体 LAN/Tailscale 地址 + `--trusted-host <ip>` + `--allow-remote-privileged-methods`。
