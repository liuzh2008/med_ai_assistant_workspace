- 关键事实：Node ≥22.19（推荐 24 LTS）、pnpm 11.x；npm 方式 `npm i -g @deepseek-ai/dsh`（latest 0.1.1-rc.2）；源码方式 clone + `pnpm install && pnpm run build && pnpm dsh web`；默认端口 3080。
- 配置树：`$DSH_HOME/profiles/web/`（package.json `dsh.profile.bundles` → `cordis.patch.yml` 用户层 → `--patch` overlay）；`pnpm dsh web --dump-config` 预览合成树。
- 安全红线：**`--host 0.0.0.0` 被 DSH 禁止**（RCE 风险）；远程访问 = 绑具体 LAN IP + `--trusted-host <host>` +（可选）`--allow-remote-privileged-methods`；或 Nginx 反代（需 Upgrade/Connection 头支持 SSE）+ TLS + 认证。
- 进程守护（Windows 已验证模板，位于 `C:\Users\Administrator\.dsh\`）：`start-dsh.cmd`（幂等启动+依赖检查）→ `watchdog-dsh.ps1`（端口探活+10min 防抖+拉起 `watchdog-launch.cmd`）→ 计划任务每 5 分钟触发；手动重启用 `restart-dsh.ps1`（动态找监听进程树 → taskkill /T /F → 等端口释放 → 重启）。Linux 用 systemd `Restart=always`。
- 备份：`~/.dsh` 整目录（sessions/storages/attachments/profiles/`.credentials.yaml`——含 API 密钥，须加密）。
- **离线部署（生产服务器无法联网，§2.3）**：node_modules 含平台二进制 → 构建机必须与生产机**同 OS/arch/Node 大版本**；pnpm 的 node_modules 是 junction/symlink → **禁 xcopy/robocopy**，用 tar（跟随链接展开）整包拷贝 或 `pnpm store + pnpm install --offline --frozen-lockfile`；生产机 Node/pnpm 一并离线安装。离线升级 = 重新构建整包 → 覆盖代码目录（保留 $DSH_HOME）→ 重启。
- **LLM 通道（§6.5，本项目已验证兼容）**：生产执行服务器 M3 代理 `POST /api/dsh-llm/chat/completions`（`DshLlmProxyController`，@Profile execution + `medai.llmproxy.enabled=true`；`Authorization: Bearer <每机token>`（SHA-256 哈希注册 `medai.llmproxy.machines[]`）；限流默认 60/min/机；content-type 声明 NDJSON 但实际**透传 DeepSeek SSE 行**（`data: {...}`+`data: [DONE]`，PiiCleanser 只做子串替换不动行结构）→ 与 DSH `llm-deepseek` 适配器（`POST {baseURL}/chat/completions`+Bearer+`parseSse`）完全兼容。**DSH 配置**：`$DSH_HOME/settings.yaml` 的 `llm-deepseek: {baseURL: http://<执行服务器>:8082/api/dsh-llm, apiKeyEnv: DSH_MACHINE_TOKEN}` + `agent-default-model: {provider: deepseek-official, model: deepseek-v4-flash}`。API key 只存在于执行服务器（唯一出网口）。
- **openEuler 生产落地（§10）**：生产 DSH 机 openEuler 22.03 x86_64 / 10.120.11.43 / 无法联网；构建机候选 **100.66.1.4（Ubuntu 24.04 x86_64 有网，Node v18 需升级 24）**；tar 整包 + systemd unit（`Environment=DSH_HOME=/var/lib/dsh` 等）。待确认参数 5 项：生产主服务器 IP（MCP /mcp 地址）、执行服务器 machines 注册表、每机 token 生成、构建机确认、防火墙放行（3080→执行服务器 8082、主服务器 8081）。

### 2026-08-14 测试库 → 本机开发库 Oracle 同步流程（expdp/impdp）
前提：两端同为 21c、应用 schema 都是 SYSTEM、system/Liuzh_123。
1. 收集两端差异：表清单 `all_tables WHERE owner='SYSTEM'`、列清单 `all_tab_columns`（空字段用 `NVL(TO_CHAR(...),'-')` 占位再 `||` 拼接，避免空字段错位；**不能带 data_default**，LONG 会 ORA-00932）。
2. 测试服务器导出（容器内）：parfile 上传 `docker exec -i med-ai-oracle bash -c 'cat > /tmp/export.par'`，内容单行 `TABLES=SYSTEM.<76张应用表逗号分隔>`（排除 AQ$/LOGMNR/LOGSTDBY/MVIEW/OL$/ROLLING$/SCHEDULER_/SQLPLUS_PRODUCT_PROFILE/PRODUCT_PRIVS），然后 `docker exec med-ai-oracle expdp system/Liuzh_123@//localhost:1521/XE PARFILE=/tmp/export.par`，dump 在容器 `/opt/oracle/admin/XE/dpdump/`。
3. 传输：`docker cp med-ai-oracle:<dump> /home/liuzh2008/medai/downloads/` → `scp liuzh2008@100.66.1.4:... D:\oracle_dump\`（**路径无空格**）。
4. 本机导入：`CREATE OR REPLACE DIRECTORY DSH_DUMP AS 'D:\oracle_dump';` 然后 `impdp system/Liuzh_123@//127.0.0.1:1521/FREE PARFILE=D:\oracle_dump\import.par`（TABLE_EXISTS_ACTION=REPLACE）。
5. 导入后四件套（脚本在 `backend/test-scripts/`）：
   - `create-sequences.sql`：补建测试库命名序列（25 个）+ `ALTER TRIGGER COMPILE`；
   - `post-import-fix.sql`：回补本机独有列（ALTER TABLE ADD）、身份列 `MODIFY (... GENERATED BY DEFAULT AS IDENTITY (START WITH LIMIT VALUE))`、`ALTER PROFILE DEFAULT LIMIT PASSWORD_LIFE_TIME UNLIMITED`；
   - `resync-sequences-static.sql`：显式 (序列→表.列) 映射把序列 RESTART 到 MAX+1（**不能靠 PK 元数据**，多数表无 PK 约束）；
   - `replace-view.sql`：V_INP_BILL_DETAIL_INFO 等视图用测试库 DDL 重建。
6. 验证：USERS=35、USER_DEPARTMENTS=106、RBAC_USER_ROLES=2、DEPARTMENTS=5，触发器 `all_objects status='VALID'`。

### 2026-08-18 aTrust 命令行操作途径（本机 2.5.16.31，无官方 CLI）
- 官方无面向用户的 CLI；本机可控手段依次为：
  1. 服务级（最简单，需管理员）：`Stop-Service aTrustService` / `Start-Service aTrustService`（Auto 启动，主程序 aTrustAgent.exe，位于 `C:\Program Files (x86)\Sangfor\aTrust\`）；启停即断/连 VPN，但登录认证仍是 GUI 流程（已保存会话则自动重连）。
  2. 开源自动化登录：kenvix/aTrustLogin（Python+Selenium 自动填账号/TOTP/绕验证码，--keepalive 保活重连；或 Docker 镜像 kenvix/docker-atrust-autologin，基于 docker-easyconnect 作 socks5/http 代理）。
  3. 官方 aTrust PC SDK（CSSDK）：业务系统编程集成认证，文档 bbs.sangfor.com.cn/atrustdeveloper/pcsdk/。
  4. 本机 aTrustClientTools.exe 等工具 exe 直接调用报 "get digital sign failed"（需签名环境，非公开 CLI）。
- 关联：git-push-github 技能"终极手段"= 断开 aTrust 重试，可直接用 Stop-Service/Start-Service 替代手工托盘操作。
