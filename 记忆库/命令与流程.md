### 2026-08-14 测试库 → 本机开发库 Oracle 同步流程（expdp/impdp）
前提：两端同为 21c、应用 schema 都是 SYSTEM、system/Liuzh_123。
1. 收集两端差异：表清单 `all_tables WHERE owner='SYSTEM'`、列清单 `all_tab_columns`（空字段用 `NVL(TO_CHAR(...),'-')` 占位再 `||` 拼接，避免空字段错位；**不能带 data_default**，LONG 会 ORA-00932）。
2. 测试服务器导出（容器内）：parfile 上传 `docker exec -i med-ai-oracle bash -c 'cat > /tmp/export.par'`，内容单行 `TABLES=SYSTEM.<76张应用表逗号分隔>`（排除 AQ$/LOGMNR/LOGSTDBY/MVIEW/OL$/ROLLING$/SCHEDULER_/SQLPLUS_PRODUCT_PROFILE/PRODUCT_PRIVS），然后 `docker exec med-ai-oracle expdp system/Liuzh_123@//localhost:1521/XE PARFILE=/tmp/export.par`，dump 在容器 `/opt/oracle/admin/XE/dpdump/`。
3. 传输：`docker cp med-ai-oracle:<dump> /home/liuzh2008/medai/downloads/` → `scp liuzh2008@100.66.1.4:... D:\oracle_dump\`（**路径无空格**）。
4. 本机导入：`CREATE OR REPLACE DIRECTORY DSH_DUMP AS 'D:\oracle_dump';` 然后 `impdp system/Liuzh_123@//127.0.0.1:1521/FREE PARFILE=D:\oracle_dump\import.par`（TABLE_EXISTS_ACTION=REPLACE）。
5. 导入后四件套（脚本在 `backend/test-scripts/`）：
   - `create-sequences.sql`：补建测试库命名序列（25 个）+ `ALTER TRIGGER COMPILE`；
   - `post-import-fix.sql`：回补本机独有列（ALTER TABLE ADD）、身份列 `MODIFY (... GENERATED BY DEFAULT AS IDENTITY (START WITH LIMIT VALUE))`、`ALTER PROFILE DEFAULT LIMIT PASSWORD_LIFE_TIME UNLIMITED`；
   - `resync-sequences-static.sql`：显式 (序列→表.列) 映射把序列 RESTART 到 MAX+1（**不能靠 PK 元数据**，多数表无 PK 约束）；
   - `replace-view.sql`：V_INP_BILL_DETAIL_INFO 等视图用测试库 DDL 重建。
6. 验证：USERS=35、USER_DEPARTMENTS=106、RBAC_USER_ROLES=2、DEPARTMENTS=5，触发器 `all_objects status='VALID'`。

### 2026-08-14 本机后端启动（dev 模式）

### 2026-08-13 前端诊断匹配逻辑验证流程（med_ai_assistant_1.0_bs_vue）
- 单测：`npm run test:diagnosis`（node --test 跑 test/diagnosis/*.test.mjs，纯函数测试，无 Vue 环境）。
- 组件语法验证（替代全量 build，避免 echarts 缺依赖阻断）：node 脚本用 `@vue/compiler-sfc` 的 parse+compileScript+compileTemplate 和 `@babel/parser` 校验 .vue 文件；全量 build 本地缺 `node_modules/echarts` 会失败（环境问题，非代码问题）。
- E2E 模拟：临时 .mjs 脚本把 diagnosisParser/diagnosisMerge 的 `'@/utils/x'` 重写为 `'./x.js'` 后写入 src/utils 再动态 import（相对脚本位置用 `../../src/utils/...`），用完删除。
- 提交推送：三仓库独立（backend / vue / 根），vue 有未暂存改动时 `git stash push -m ... -- <file>` → `git pull --rebase` → `git stash pop` → `git push`；推送被拒（remote 有新提交）时先 rebase 再推。
