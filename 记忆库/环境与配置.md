- **MCP streamable-http 传输要求**：Accept 头必须同时含 `text/event-stream` 和 `application/json`（缺一报 "Invalid Accept headers. Expected TEXT_EVENT_STREAM and APPLICATION_JSON"）；initialize 后后续请求需带 `Mcp-Session-Id` 头。
- **✅ 已解决（P0 streamable-http 反序列化 500）**：根因 = MCP SDK 0.18.x 的 `WebMvcStreamableServerTransportProvider.handlePost` 用 `request.body(String.class)` 读请求体，Content-Type application/json 时 Spring 用 Jackson 把 `{..}` 反序列化成 String → "Cannot deserialize String from Object (START_OBJECT)"。
- **修复**：`McpServerConfig` 加 `WebMvcConfigurer.extendMessageConverters`，在转换器链最前插入支持 application/json 的 `StringHttpMessageConverter`，让 String body 走原始字符串读取。**验证通过**：真实 MCP SDK client（Java 0.18.3 `HttpClientStreamableHttpTransport`，脚本 `backend/temp/McpClientTest.java`）成功 connect→initialize→listTools，返回 `TOOL: medai_system_ping`。
- **排查链（已排除）**：①手写格式（真实 SDK client 也失败）②Jackson 版本（`jackson-bom.version=2.20.1` 仍复现）③MCP SDK patch（0.17.0/0.18.2/0.18.3 均复现，行号 416→444 变化证明版本已变）④McpJsonMapper bean（`@Primary` 覆盖仍复现）→ 最终字节码确认 `request.body(String.class)`。
- **当前 pom 状态**：Spring AI **1.1.6**（1.0.3→1.1.6，streamable-http）、`jackson-bom.version=2.20.1`、`mcp-sdk.version=0.18.3`（覆盖 Spring AI 默认 0.18.2）+ WebMvcConfigurer workaround。**注**：Jackson 2.20.1 与 MCP SDK 0.18.3 覆盖是排查副产物，非必需（真正的修复是 workaround），SDK 升到 1.0+（mcp-json 并入 mcp-core，结构已变）会破坏 Spring AI 1.1.6，故用 workaround。后续 SDK 升级后可移除 workaround。
- **工具链**：Java 21.0.4、Maven 3.9.10、Node v24.11.1、pnpm 11.21.0。DSH checkout `custom/medai` @ `8b73ae4a27`。
- **✅ P0 端到端通过（2026-08-15 完成，用户实测）**：DSH 新对话调用 `medai_system_ping` 返回 `"pong"`，MCP 全链路 connect→initialize→tools/call 三步握手成功（纯 HTTP 可复现命令已存 `记忆库/会话记忆.md`）。两个收尾关键补丁：
  - **mcp-client 必须装进 profile**：`@deepseek-ai/dsh-mcp-client` 是 DSH 内置插件，但**不随默认 bundles（dsh-base/dsh-web-app）加载**——需 `node --import tsx/esm apps/cli/src/bin.ts plugin --profile web add @deepseek-ai/dsh-mcp-client`（npm 版 0.0.1-rc.1，含 streamable-http 支持；本地 checkout 是 0.1.0-rc.5）。否则 `cordis.patch.yml` 的 `name:` 无法解析、DSH 静默跳过 MCP 配置（现象=工具不出现且无报错）。
