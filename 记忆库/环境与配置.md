### 2026-09-04 本机 Oracle（OracleServiceFREE，21c SE2）内存占用 20GB 根因 + 已收敛至 ~6.6GB
- **现象**：本机 oracle.exe 单进程占物理内存 ~20.2GB（占整机 63.8GB 已用内存 36.7GB 的一半以上）。
- **根因（配置锁定，非泄漏）**：spfile `D:\APP\ADMINISTRATOR\DATABASE\SPFILEFREE.ORA` 显式写死 `sga_target=20602421248(≈19.2GB)`、`pga_aggregate_target=6854541312(≈6.4GB)`、`processes=2240`——实例启动即整块锁定 SGA。SGA 构成：Database Buffers **16.7GB（占 87%）** + Shared Pool 2.2GB + Streams 0.5GB + Large 0.1GB；PGA 实际仅用 0.42GB。**负载证据**：缓存命中率 99.96%，`v$db_cache_advice` 显示 buffer cache 砍到 1.6GB 物理读因子仍 1.0 → 16.7GB 属按"64GB 机器 40%"拍脑袋的过剩配置。
- **收敛动作（2026-09-04 已执行并重启生效）**：sqlplus `/ as sysdba` 执行 `alter system set sga_max_size=8G scope=spfile; alter system set sga_target=6G scope=spfile; alter system set pga_aggregate_target=2G scope=spfile; alter system set processes=500 scope=spfile;` → 重启 `OracleServiceFREE`。**效果**：oracle.exe 物理占用 20.2GB→**6.6GB**；整机内存已用 36.7→23.3GB（可用 27.2→40.5GB，使用率 57%→37%）；实例 OPEN、61 个应用会话自动重连、监听器正常（MedAi 后端连接池自愈，无需人工干预）。
- **回滚命令**（如需恢复原值）：将上表 4 参数改回 sga_max_size=19648M / sga_target=20602421248 / pga_aggregate_target=6854541312 / processes=2240 后重启服务。
- 关联：ORACLE_HOME `d:\download\windows.x64_213000_db_home`（见 2026-08-14 条目）；改 spfile 涉及 sga_max_size/processes 的**必须重启**才生效。
